# 骑手结算类型错误修复与验收

日期：2026-09-04。范围：用户同意处理校园地图发布验收中发现的两处财务模块编译错误。不部署、不访问线上数据库、不更改结算政策。

## 根因和修复

`generateRiderSettlements` 的 `Promise.all` 中，冻结记录查询的空分支使用未标注类型的 `[]`。TypeScript 5.9.3 实际推断 `holds` 为 `never[] | { status: string; orderId: string }[]`，两处 `filter` 回调的参数推断成 `never`，因此访问 `item.status` 报错。

新增从 Prisma `ErrandSettlementHold` 模型取出 `orderId`、`status` 的类型化空数组，并仅替换该查询的空分支。没有使用 `any`、类型强制断言、忽略编译错误或改变数据库 schema。

业务 SQL 条件、`released` 判断、申诉/风险排除、营销订单解冻条件、结算金额和 `PENDING` 状态保持不变。
