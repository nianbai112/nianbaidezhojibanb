## 代码问题与证据边界

生产与本地的聊天 Service、Worker、AI Runtime 源码 SHA-256 一致。

`wechat-chat.service.ts` 的 `generate` 方法在模型调用成功、结算额度后执行回复校验：空回复或超过 `maxReplyChars` 都抛出“回复为空或超过长度限制”。`wechat-chat.worker.ts` 将发送前捕获的各种异常统一记录为 `generation_failed_or_quota_exhausted`，后台再翻译为“生成失败或额度不足”。因此这个提示不能证明额度不足。

使用生产编译模块、内存假数据库和模拟模型响应进行了四个复现，不调用真实模型、不写数据库、不发送微信：

| 条件 | 结果 |
| --- | --- |
| 上限 500 字，返回 501 字 | 抛出回复校验错误 |
| 上限 500 字，返回 500 字 | 通过 |
| 上限 2,000 字，返回 501 字 | 通过 |
| 返回空内容 | 抛出相同回复校验错误 |

现有证据将调查重点定位到生成成功后的本地处理，回复校验是首先应修复的环节。历史日志隐藏了回复正文，且没有保存字符数、模型 `finish_reason` 和任务对应的调用 ID，因此不能把“超长回复”或“空回复”中的任何一个断言为这两次事件的唯一原因，也不能仅凭时间匹配完全排除随后数据库操作异常。500 Token 并不等于 500 字。
