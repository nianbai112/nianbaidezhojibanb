# 校园地图 B 方案：Go 读取服务第一阶段

日期：2026-09-04。状态：本地实现与分项验证完成，未部署、未切换生产流量。

## 已落地范围

- 独立 Go 进程服务已发布地图；NestJS 保留采集、审核、编辑、发布的唯一写入权，不迁移或删除现有地图数据。
- 固定学校白名单、后台定时同步、内存快照、预压缩、内容摘要、短时有效期、并发上限、超时、健康探针与指标。
- 受保护读取每次仍由原 JwtGuard 检查登录及账号状态；新增内部入口要求独立服务密钥和回环连接。其限流按令牌摘要区分，避免同一校园 NAT 共用一个额度。
- 小程序兼容内容摘要：正式版本号不变时，撤回内容仍能在页面重新显示并请求后刷新；刷新失败时清除已通过 Go 加载的旧导航状态。没有改动地图视觉、坐标、路网算法。
- 提供 systemd 资源限制、Nginx 分流和手动回切示例，默认仍指向原 Node 服务。

实现与部署步骤见 [服务说明](../../services/campus-map-read/README.md)。

## 不能省略的上线关口

1. 完整后端构建和测试；确认原鉴权、封禁、撤回、停用、回滚行为。
2. 测试环境部署并执行 `nginx -t`；当前仅有配置示例，没有验证生产 Nginx 匹配关系。
3. 按学校数、开学峰值同时访问人数和刷新频率，压测真实登录/数据库链路；测试共用校园出口 IP、冷启动、超时、过载、重启和回切。
4. 小程序真机验证同版本撤回、失败清理、恢复加载与导航；打开页面不会无请求自动获得服务器撤回。
5. 小流量逐步切换；评估 CDN、备用机器和故障切换。未提供容量数据前，不承诺任何“万人在线”指标。

## 可用性边界

Go 拆分减少地图重复查库与序列化，不会自动解决 SVG 绘图卡顿。受保护读取仍依赖 Node 的实时身份检查；上游故障时返回错误，公开地图只保留剩余短租期，不无限提供旧路线。同机部署仍共享主机、网络和数据库故障点，不是双机高可用。

结论：这是 B 方案的可验证第一阶段，不是整个校园地图已全部用 Go 重写，也不是开学高可用保障已经验收。
