## 生效行为

| 字段 | 填 0 | 填非零值 |
| --- | --- | --- |
| 每日调用上限 | 不检查微信聊天每日次数上限，继续记录次数 | 按设置限制，并发调用不能重复占用最后一次额度 |
| 每日 Token 上限 | 不检查微信聊天每日 Token 上限，继续记录用量 | 预占后按实际用量结算 |
| 回复字数上限 | 保留完整回复，不替换为默认 500 字 | 超出时按 Unicode 码点截短，不截断 emoji 的代理对，记录“回复已按字数上限截短” |
| 单次输出 Token | 请求中省略 `max_tokens`，不传 0、不回退到全局默认数值 | 将设置值传给模型 |

0 表示取消该应用字段的限制，不能取消模型服务本身的默认输出范围、上下文容量、账号权限或余额限制。模型的 `finish_reason=length` 表示达到输出或上下文长度限制，详见 [DeepSeek 接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)。

如果单次输出为 0、每日 Token 非零，会预占剩余每日额度，避免并发请求重复占用；本次模型调用按实际用量结算，能够跨过剩余额度，之后停止新的调用。模型调用失败或结果未知时保留预占，不自动执行收费重试。页面已显示此规则。AI 运营中心的全局限额独立生效。

冷却时间、上下文条数、表情程度的含义保持独立，没有将所有数字 0 都解释为无限。负数、小数、字符串 `"0"`、空值、布尔值仍会被后端拒绝。

错误现在分为：微信每日次数／Token、全局限额、密钥或权限问题、模型超时／限流／请求错误、空回复、达到输出上限但无正文、额度记账异常、本地处理异常、微信发送拒绝／结果未知。旧的混合错误显示为“历史生成失败（旧日志未区分具体原因）”，没有伪造旧记录的具体原因。

任务中新增调用记录 ID、模型结束原因、输入／输出 Token、原回复和处理后字数等诊断信息。通用调用日志不保存微信聊天正文或供应商回显的私人内容；调用 ID 与任务 ID 可以关联排查。预览和自动回复使用同一套回复处理规则。

MySQL 的回复文本列扩展为 `LONGTEXT`，支持取消字数上限后的较长回复。迁移 `202609270003_wechat_reply_limits` 已执行，原 42 项迁移保持原校验和，新台账共 43 项 APPLIED；旧回复文本逐条哈希一致。
