# 代买规格库（杯型 / 口味 / 加料）实施记录

2026-09-27。本次完成第一期：后台可自行配置温度、糖度、加料等规格，小程序按分组选择，服务端计价并写入订单快照，骑手端按口味采购。

## 规格模型

| 层级 | 放在哪里 | 说明 |
| --- | --- | --- |
| 杯型 / 份量 | 商品的规格表（原 `purchase_skus`） | 每个商品单独定价和重量，例如中杯 ¥12、大杯 ¥15 |
| 口味属性 | 店铺规格库，类型「口味属性」 | 温度、糖度、奶底等；可设必选、最多选几项、默认值、个别选项加价 |
| 加料 | 店铺规格库，类型「加料」 | 珍珠、奶盖等；按份计价，可设每种最多几份、每杯最多几份 |

规格组属于店铺。商品勾选要用的规格组，可以对单个商品隐藏选项（例如只做冰的饮品隐藏「热」），也可以覆盖默认值。组的展示顺序由规格库统一决定。

## 后台操作

1. 「代买服务 → 规格库」：选择店铺，点「新建规格组」，选类型，填写选项名称和加价。
2. 「商品与规格」：编辑商品，在「杯型 / 份量」里填各杯型价格，在「口味与加料」里勾选规格组。
3. 售罄：在规格库卡片上直接切换选项的「有货 / 售罄」，挂载该组的商品立即不能再选这一项。

停用的规格组或选项不会删除，已下单商品的快照不受影响。

## 计价

```
单杯价   = 杯型价 + Σ 口味加价 + Σ（加料单价 × 份数）
商品货款 = Σ 单杯价 × 杯数
```

金额全程按「分」计算。服务端按当前规格库重新计价；价格或选项变化会改变报价签名，走原有「请重新确认报价」流程。

服务端校验：选项必须属于商品已挂载、已启用的规格组且未被隐藏；必选组必须选；单选组最多一项；加料每种和每杯份数不超上限；售罄选项不能下单。同一杯型、口味完全相同的商品合并为一行，口味不同则分行。

## 兼容

- 没有挂载规格组的商品，选购、报价和快照与原来一致。
- 旧版小程序不传口味时，服务端按默认值下单；必选组没有默认值时提示用户更新小程序。
- 新版小程序遇到尚未升级的服务端，结算页拒绝提交带口味的商品，避免加料少收钱。
- 用户本地保存的旧购物车按普通商品处理；商品新增必选组后，这些行提示重新选择。
- 历史订单快照没有口味字段时，页面回退显示原规格名。

## 骑手端

- 小程序骑手页和骑手 App 显示每件商品的完整口味，每家店有「复制点单」，复制该店的点单清单。
- 采购变更可以修改口味，例如门店珍珠卖完时去掉珍珠。单价按目录重算，仍可按门店实价修改；差价走原有确认、补款和退款流程。
