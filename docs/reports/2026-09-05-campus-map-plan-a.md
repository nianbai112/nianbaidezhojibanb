# 校园地图方案 A 修复与本地验收

日期：2026-09-05。范围：当前 Nest 后端、Vue 管理后台、Go 地图读取服务，以及桌面的「前端文件」。

本轮已修复分析中确认的数据刷新、锚点覆盖、编辑保存、入口连线缺口，接入现有客服反馈，并减少不必要的加载和覆盖物重建。未部署、未修改真实地图数据、未执行数据库迁移、未上传小程序。

## 已完成的行为

| 问题 | 当前行为 |
| --- | --- |
| 同版本撤回不能刷新 | Nest 在公开过滤之后生成 readRevision，Go 沿用此版本；新增轻量版本查询，前端每次请求完成后间隔 15 秒检查，同一正式版本撤回也会更新。 |
| 长时间停留使用旧地图 | 页面可见时检查；导航开始前复核超过 5 秒的状态；读取失败清空旧图和路网，后续成功后恢复。轮询间隔不等于端到端撤回时限，请求、鉴权重试和 Go 同步仍占用时间。 |
| 页面切换与迟到请求 | 隐藏时停止轮询和持续定位，迟到请求不得覆盖新学校或隐藏页面；返回后验证版本再恢复导航。到达后不重新启动定位，定位权限错误只停止导航，不清除已确认的新地图。 |
| 后台移动地点不生效 | 已发布 artworkAnchorX/Y 优先于本地默认锚点；支持画布边缘 0 坐标，null 不充当 0。 |
| 底图绑定不明确 | 发布包携带 artworkId，前端核对区域和底图身份；兼容明确指向原 SVG 的旧配置。当前仍仅内置重庆城乡发展职业学院这一张底图，其他学校底图需要单独适配，不能据此宣称已支持任意学校。 |
| 保存或发布期间继续编辑 | 以编辑序号判断本次请求保存了哪些修改；后续编辑保留待保存状态，自动保存重新排队；并发保存复用请求，旧学校响应不得覆盖当前工作流。 |
| 编辑任一点重建整张高德图 | 按对象身份和内容复用未变化的覆盖物；连续编辑合并刷新，仅替换变化对象。 |
| 入口距离近就生成已核验通路 | 取消 60 米自动补线，仅允许入口与实采道路之间 5 米内的定位吸附。生成坐标沿已采道路，入口较远时发布明确要求补采。5 米是数据吸附容差，不是实地可通行证明。 |
| 无障碍路线绕过台阶属性 | 入口衍生边保留原道路楼梯属性；有楼梯时不能继承轮椅通行。 |
| 旧发布版本含不安全连接线 | 公开读取时暂停旧自动入口连接图的导航，浏览仍保留。原不可变版本未被改写；需要按新规则核查并重新发布。 |
| 地图报错进入通用微信反馈 | 「地图有误」由学生填写并确认，提交现有 feedback 客服工单，携带地点 ID、地图、来源校园和正式版本；不自动上传当前位置。请求未确认时重试复用幂等标识，成功后可查看工单进度。 |
| 下载最终不会使用的地图资源 | 插画页面跳过工程路线图层、原生地图预处理和会被本地 SVG 替换的远程底图；版本不变不下载完整地图。 |

地图反馈复用现有「客服工作台」受理和回复。运营根据工单中的地点和版本，在现有地图采集工作台安排核查，审核、发布后在同一工单回复处理结果；本轮没有另造自动派单/自动结单系统。

## 发布前必须完成的实际验收

1. 先在隔离数据副本核对当前学校、底图标识、每个入口与实采道路的位置。距道路超过 5 米的入口需补采，不能提高阈值掩盖现场缺口。
2. 协调后端更新与地图重新发布：含旧自动连接线的公开版本在新后端下会暂停导航；重新保存/发布会写入底图身份并生成入口规则版本 2。
3. 更新 Go 二进制与小程序包后，实测停用、地点和照片撤回、前后台切换、断网恢复、拒绝定位、到达、反馈受理和回复。旧客户端不能替代新版生命周期验收。
4. 用真实数据库与部署依赖进行联调和峰值压测，再按既有灰度流程切换 Go 流量。轻量 Nest 版本接口减少传输量，仍读取当前公开数据；不能据局部测试承诺万人并发或主机故障高可用。

推荐继续沿用方案 A 分项验收和部署。整体重写没有必要；本轮修复不等于生产发布或现场导航精度已经验收。
