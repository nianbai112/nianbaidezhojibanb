## 已确认的接口/客户端问题

| 问题 | 线上证据 | 影响与修复归属 |
| --- | --- | --- |
| 置顶订单请求带 undefined 用户 ID | 微信 UA 的 `/api/topnotes/user-orders/undefined` 在 24 小时内 175 次 401，今早仍出现；应用日志提示未提供令牌 | `components/PaidPinning.js` 直接调用 `getUserOrders(userInfo.value.id)`，缺少未登录/ID 就绪保护。应改小程序，后端保持认证和归属校验。此处是帖子付费置顶订单，不是宿舍小店订单。 |
| 骑手排行榜 404 | 微信 UA 11 次 404，服务器内部读取也复现 | 兼容中间件剥掉 `/api`，控制器只注册 `api/rankings`，路径对不上。属于后端兼容路由问题，本次优惠券部署未修改该控制器。 |
| 富文本分类接口路径不一致 | 有效校园 ID 的旧请求路径出现 404；内部 `/api/rich-text-content/config/region/.../all-types` 为 200，缺 `/api` 的内部路径为 404 | 对齐 Nginx 重写、全局前缀、中间件和客户端契约；另外客户端请求区域 `1` 与空 ID 的情况需要前端输入保护。 |

匿名请求受保护接口返回 401 本身是正确行为。问题在于客户端无有效身份仍发起依赖个人身份的请求；不应通过去掉后端鉴权来修复。
