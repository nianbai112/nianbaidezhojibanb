# 代买店铺接飞鹅云打印机：文档要点与代码分析

日期：2026-10-06
范围：后端/后台主工作文件夹 `~/Desktop/后端后台本地测试版`（分支 codex/code-audit-20260727 及未提交改动，代买模块只在这里），飞鹅开放平台官方文档 help.feieyun.com（2026-10-06 阅读）。
本文件只做分析，没有改代码。生产服务器的打印机配置和打印记录没有查看（只读查询被权限拦截），文中关于线上状态的说法都需要你确认。

## 结论

1. 系统已经有一套完整的云打印模块，目前给外卖商家用（`backend/src/modules/print/print.service.ts`）。它支持飞鹅、易联云、芯烨、佳博，飞鹅下单、查询打印结果、凭证加密、Worker 队列、去重和补打都已经写好。
2. 代买订单现在完全不会触发打印：打印机绑的是外卖商家（`PrinterConfig.merchantId`），代买的店铺是平台录入的外部门店（`PurchaseShop`），和商家没有关联；打印模块也只认外卖 `Order`。
3. 接入工作量中等，复用现有模块即可：让打印机可以绑代买店铺，打印任务支持代买业务类型，再写一个代买小票模板。触发方式参考订单群播报：用 Worker 轮询，不改动接单和支付代码。
4. 动手前要先定一件业务上的事：**什么时候打印**，以及**店家已经做好、订单却被取消时谁来承担**。下面第三节会细讲。
5. 现有打印模块有 1 个安全问题、2 个可靠性问题，在把平台托管打印机放进代买店铺之前必须修好（第五节）。

## 一、飞鹅云文档要点

### 账号与设备

- 在 admin.feieyun.com 注册开发者账号，个人中心可以拿到 USER 和 UKEY。注意 UKEY 是账号密钥，和机身上的设备 KEY 不是一回事。开放平台接入流程里有一步"资质认证（3 个工作日）"，最好先把账号注册好。
- 打印之前，必须先把设备的 SN 和 KEY（印在机身底部标签上）添加到开发者账号。可以在飞鹅后台手动添加，也可以调 `Open_printerAddlist` 接口，每次最多 100 台。
- 一台设备最多绑定 3 个飞鹅账号，超出时返回"一台打印机最多只能绑定 3 个账户"，需要先从旧账号删除。

### 请求规则

- 所有接口都只能用 `POST`，`Content-Type: application/x-www-form-urlencoded`。
- 公共参数：`user`、`stime`（10 位秒级时间戳）、`sig = sha1(user + UKEY + stime)`（40 位小写）、`apiname`。服务器时间和北京时间差太多时，会返回 `-3 请求超时`。
- 判断结果只看 `ret`：0 表示成功，非 0 表示失败；限流时返回 `ret = -5`。
- **URL 分流**：飞鹅 2026-01-15 发了公告，每个接口改用独立 URL，旧的统一 URL 在 2026-08-01 完全下线。现有代码已经用的是新 URL（`/Api/Open/printMsg`、`/Api/Open/queryOrderState`），不受影响。

### 接口一览（中国站 `https://api.feieyun.cn/Api/Open/<名称>`）

| apiname | 用途 | 现有代码 |
| --- | --- | --- |
| Open_printerAddlist | 批量添加设备（必接） | 未接，需手动去飞鹅后台添加 |
| Open_printMsg | 小票机打印 | 已接 |
| Open_printLabelMsg | 标签机打印（标签机必须用这个，用错了机器只响不打） | 未接 |
| Open_printWmOrder | 美团/淘宝闪购/京东外卖模板打印 | 不需要 |
| Open_printerDelList / Open_printerEdit | 删除 / 修改设备 | 未接 |
| Open_delPrinterSqs | 清空设备待打印队列 | 未接 |
| Open_queryOrderState | 查询某张单是否打印成功 | 已接 |
| Open_queryOrderInfoByDate | 某设备某日已打印/待打印数量 | 未接 |
| Open_queryPrinterStatus | 离线 / 在线正常 / 在线异常（一般是缺纸） | 未接 |
| Open_printerInfo / Open_getModel | 机型：0=58mm、1=80mm、2=标签机、3=出餐宝、4=打印扫码一体机 | 未接 |
| 打印状态回调 | 打印成功后飞鹅回调 `backurl` | 未接，目前靠每分钟轮询 |

### Open_printMsg 关键参数

- `sn`：设备编号。
- `content`：打印内容，不超过 5000 字节。
- `times`：打印联数。
- `expired`：订单失效时间戳，超过这个时间就丢弃不打；最长是当前时间往后 24 小时。**现有代码没有传这个参数。**
- `backurl`：回调地址，要先在飞鹅后台加入白名单。

### 排版与语音

- 排版标签：`<BR>` 换行、`<CUT>` 切纸、`<C>` 居中、`<CB>` 居中放大、`<B>` 放大一倍、`<L>` 加高、`<W>` 加宽、`<BOLD>` 加粗、`<RIGHT>` 右对齐、`<QR>` 二维码（每单只能一个）、`<BC128_A/B/C>` 条形码。
- 每行字数：58mm 是 16 个汉字或 32 个字母，80mm 是 24 个汉字或 48 个字母。现有模板的分隔线是 32 个 `-`，按 58mm 排版。
- 语音指令放在票尾：`<AUDIO-COMMON>` 播"你有新的订单"，`<AUDIO-CANCEL>` 播"有用户申请取消订单了"，`<AUDIO-REFUND>` 播退单。不带指令时播默认的新订单提示。代买的取消单正好可以用 `<AUDIO-CANCEL>`。

### 可靠性方面要知道的（对代买很关键）

- 接口返回成功只代表"发送成功"。机器关机或离线时，接口照样返回成功。要确认是否真的打出来，得用返回的订单号查 `Open_queryOrderState`，或者等回调。
- 订单缓存在飞鹅云端。设备掉线后大约 4 分钟会自动重连，重连后继续打；缺纸时装好纸会补打。没打印的单在云端保留 1～7 天。
  → **如果不设 `expired`，一台晚上断网的打印机，第二天早上可能会把昨晚的单（包括已经取消的）全部打出来。**
- 打印状态查询有 5 秒缓存；"离线"指设备和服务器失联超过 2 分钟。
- 回调：用 HTTPS POST 发送 `orderId`、`status=1`、`stime`、`sign`。签名要用飞鹅公钥做 SHA256withRSA 验签；必须在 5 秒内返回 `SUCCESS`，否则飞鹅会重推。

## 二、现有代码盘点

### 可以直接复用的

- `print.service.ts`：
  - 打印任务表 `PrintJob` 的状态流转：`queued → processing → submitted → printed`，失败为 `failed`，网络超时为 `uncertain`。
  - Worker 每 5 秒消费一次队列（`reconcileJobs`，第 140 行），每分钟查一次打印结果（`reconcileSubmittedJobs`，第 191 行）。
  - `dedupeKey` 唯一键防止重复出单。网络超时只记为 `uncertain`，不自动重打，避免出两张单。
  - 商家自有凭证用 AES-256-GCM 加密，需要服务器环境变量 `PRINT_CREDENTIAL_KEY`（至少 32 位）。
  - "平台托管"模式：用平台自己的飞鹅账号（配置表 key=`feie`），只支持飞鹅。
- 触发点（都在外卖里）：
  - 支付成功：`payment.service.ts` 约第 502 行。
  - 预约单到点：`shop.service.ts` 约第 250 行。
  - 免单：约第 4511 行。
  - 商家手动补打：约第 5583 行。
- 后台页面：
  - 商家打印机：`admin/src/views/merchant/MerchantPrinters.vue`。
  - 系统设置 → 第三方 → 飞鹅云平台托管：`ThirdPartySettingsPanel.vue`。
- 商家小程序也能自己添加打印机：`POST merchants/printer-config`。

### 代买为什么用不上

1. `PrinterConfig.merchantId` 绑的是外卖商家，而代买店铺是 `PurchaseShop`（`schema.prisma` 约第 7380 行），没有 merchantId。
2. `PrintService.getOrder` 只查外卖 `order` 表。小票模板 `orderReceipt`（第 871 行）是外卖格式，会打印收餐人姓名、电话和地址；代买不应该把买家手机号和宿舍号打给店家。
3. 代买支付回调（`payment.service.ts` 第 494 行）只通知骑手，不会调用打印。

### 代买流程中可以挂钩的位置

| 时机 | 位置 | 说明 |
| --- | --- | --- |
| 付款成功 → `pending_accept` | `purchase.transactions.ts` `applyPurchasePayment` | 此时还没有骑手 |
| 骑手接单 → `accepted` | `errand.service.ts` 约第 2368 行（骑手）、约第 2434 行（普通学生接单），另有后台派单 | 入口不止一个 |
| 用户取消 | `purchase.service.ts` `cancel` | `pending_accept` 阶段用户随时可以全额退款取消；到了 `accepted` 阶段，只有后台或"全部缺货"才能取消 |
| 骑手提交购买凭证 / 差价变更 | `receipt` / `propose` | 现有骑手垫付 → 审核 → 返还流程 |

商品快照里已经有 `specText`（杯型 + 口味 + 加料），小票可以直接用。

## 三、需要你拍板的业务问题

### 1. 什么时候出单

| 方案 | 好处 | 风险 |
| --- | --- | --- |
| A. 付款后立即打印 | 最快，店家最早开始做 | 这时可能一直没人接单；用户在 `pending_accept` 阶段可以随时免费取消，店家做好了却没人付钱 |
| **B. 骑手接单后打印（推荐作为默认）** | 已经有骑手负责，用户也不能再自由取消（`accepted` 阶段只有后台能取消） | 节省的时间等于骑手赶到店里的路程，通常有 5～15 分钟 |
| C. 按店铺设置：默认 B，签约店可以选 A | 合作店最快 | 需要配套规则："已出单后取消"要扣货款，或者由平台兜底 |

### 2. 店家做好的东西谁付钱

现有模式是骑手到店垫付，上传小票，平台审核后返还垫款。出单打印不改变这一点：骑手到店报取餐号、付钱、拿走。
如果想改成骑手不垫付、由平台和店家月结，那就是"货款直接结算给店家"，改动很大，建议放到第二期。

### 3. 价格变动和缺货

目录价是平台录入的，店里的实际价格可能不一样；店家发现缺货时，也没法反馈到系统里。
第一期仍然走现有流程：骑手到店后发起差价/缺货变更。小票上印一句"缺货或价格不符请告知骑手"即可。

## 四、推荐的一期技术方案

1. **数据**（一个增量迁移）
   - `PrinterConfig` 新增 `purchaseShopId`（可空），`merchantId` 改为可空。外卖相关查询都带着 `merchantId` 条件，不受影响。
   - `PrintJob` 新增 `bizType`（`shop_order` / `purchase_stop`）和 `bizId`，外卖继续用 `orderId`。
   - `PurchaseShop` 新增出单时机字段（`off` / `on_accept` / `on_pay`），默认 `off`。
2. **触发**：沿用订单群播报的做法，由 Worker 每几秒轮询，不改动支付和接单代码。
   - 找出"已到出单时机、店铺有启用的打印机、还没有出单任务"的代买单，**每个店铺（stop）各打一张**，只打该店自己的商品。去重键为 `purchase:new:<stopId>:<printerId>`。
   - 轮询能一并覆盖骑手接单、学生接单、后台派单这几个入口，不用在每个入口加代码。
   - 订单取消时，如果这张单已经出过票，补打一张取消单（`<AUDIO-CANCEL>`）。
3. **小票内容（58mm）**：
   - 平台名 + "代买单"，取餐号（订单号后 4 位）。
   - 骑手称呼和手机尾号，商品 × 数量 + `specText`。
   - 参考货款合计，并注明"骑手到店付款"。
   - 买家备注、接单时间。
   - 票尾加 `<AUDIO-COMMON>` 和 `<CUT>`。
   - **不打印**买家姓名、电话、宿舍号，也不打印买家的收货码 `receiptCode`。
4. **飞鹅调用加上 `expired`**：代买单设为出单后 30～60 分钟失效，防止离线打印机事后吐出旧单。
5. **后台**：在 `PurchaseService.vue` 的店铺编辑里加"出单打印机"，包括 SN、KEY、名称、测试打印和在线状态（调 `Open_queryPrinterStatus`）。
   - 默认用**平台托管**：代买店家没有飞鹅开发者账号，打印机挂在平台账号下。
   - 用 `Open_printerAddlist` 自动把 SN 和 KEY 加到平台账号，不用再手动登录飞鹅后台。
6. **骑手端 / 小程序**：骑手能看到"店家已出单（已打印）"，或者"打印失败，请到店现场点单"。

## 五、现有打印模块的问题（建议一起修）

1. **[高] 商家能给自己的打印机选"平台托管"。**
   - 原因：`shop.service.ts` 的 `normalizePrinterPayload`（第 5894 行）把小程序传上来的数据原样交给 `prepareConnection`（`print.service.ts` 第 539 行），后者直接接受 `dto.connectionMode === "platform_managed"`。
   - 后果：现在平台飞鹅账号下没有设备，所以没有影响。但一旦把代买店铺的打印机挂到平台账号，任何外卖商家都能在小程序里填上那台机器的 SN（机身标签上印着），选"平台托管"，再点"补打"，就能把内容打到别人店里。
   - 修法：小程序入口强制只能用"商家自有"，平台托管只能在后台设置。
2. **[中] 打印结果查询会被旧任务"堵死"。**
   - 原因：`reconcileSubmittedJobs` 每分钟按发送时间从旧到新取 50 条 `submitted` 任务，没有时间上限。永远打不出来的旧任务（设备停用或删除、飞鹅 7 天后清除）会一直占着这 50 个名额。
   - 后果：新任务的状态永远停在"已提交"，同时每分钟对飞鹅白打 50 次查询（飞鹅有限流）。
   - 修法：超过 24 小时还没打印的标记为过期；或者改用 `backurl` 回调。
3. **[中] 没有使用 `expired` 参数**：离线打印机恢复后，会把积压的旧单全部打出来，已取消或已退款的外卖单也会打。
4. **[低] 失败重试没有间隔**：`failed` 且尝试次数小于 3 的任务每 5 秒重试一次。像"设备编号和用户不匹配"这种重试也没用的错误，会在 15 秒内连试 3 次。
5. **[低] 平台托管的 UKEY 明文存在 `configs` 表**：接口返回和日志里做了脱敏；商家自有凭证是加密存储的，两边不一致。
6. **[低] 填了设备密钥却没用上**：没有调用 `Open_printerAddlist`，SN 必须先手动去飞鹅后台添加。
7. **[说明] 两个版本的打印模块不一样**：`main` 分支（本次 worktree 的基线）里是旧版，在 API 进程里同步调用飞鹅；主工作文件夹里是新版 Worker 队列。开发要基于主工作文件夹的快照，做法同之前的代买需求。

## 六、拿到打印机后先做的（不用写代码）

1. 看机身底部标签，记下 SN 和 KEY，确认型号（58mm 还是 80mm、是不是标签机）。
2. 按说明书配网（WiFi 或 4G）。
3. 注册 admin.feieyun.com 开发者账号，在个人中心拿 UKEY，然后在飞鹅后台"添加打印机"，填入 SN 和 KEY。
4. 在我们的后台 → 系统设置 → 第三方 → 飞鹅云平台托管，填写 USER 和 UKEY，并开启。
5. 在后台 → 商家打印机里，把它挂到一个测试商家下，设备归属选"平台托管"，然后测试打印，确认链路是通的。打印状态由 Worker 每分钟刷新，需要 `lingmeng-worker` 在运行。
6. 平台托管模式不需要 `PRINT_CREDENTIAL_KEY`；商家自有模式需要服务器上设置这个变量。

## 七、实现记录（2026-10-06，按用户决定）

用户决定：
- 每家代买店铺可以单独接一台打印机：选品牌（飞鹅 / 易联云 / 芯烨 / 佳博），填这家店自己的密钥。不需要的店铺不开启。
- 出单时机选方案 B：骑手接单后打印。

代码在分支 `claude/feiyun-printer-integration-801000`，基线是快照提交 81571610（主工作文件夹截至 2026-10-06 的全部内容）。

### 数据（迁移 202610060003_purchase_shop_printers，三份）

- `printer_configs`：新增 `purchaseShopId`（唯一，保证每店一台）；`merchantId` 改为可空。
- `print_jobs`：新增 `bizType`（`shop_order` / `purchase_stop`）、`bizId`、`expiresAt`。
- **顺带修复**：MySQL 里 `print_jobs.content` 和 `errorMessage` 原本是 `VARCHAR(191)`（Prisma 对 `String` 的默认类型），放不下整张小票，现改为 `TEXT`。在 MySQL 严格模式下，原来每次写入外卖打印任务都应该会失败，请上线后留意外卖自动打印是否恢复。
- PostgreSQL 版本已在本地一次性数据库上验证：用旧 schema 建库并插入数据，执行两次迁移都成功，`prisma migrate diff` 显示零差异。MySQL 版本因为本机没有 MySQL 未执行，与现有迁移用的是同一种可重复执行写法。

### 流程

- Worker 每 5 秒检查一次：最近 20 分钟内接单、店铺开启出单、这家店还没采购的代买单，每家店打一张小票。
  - 小票只列这家店的商品，印取餐码（订单号后 4 位）、骑手姓氏和手机尾号。
  - 不印买家的姓名、电话、地址和收货码。
  - 小票 30 分钟后失效：飞鹅会收到 `expired`，芯烨会收到 `expiresIn`。
- 订单取消时：
  - 小票还没发出：直接撤回；
  - 已经发出或已打印：补打一张取消单，飞鹅打印机会语音播报"有用户申请取消订单了"。
- 订单详情接口给每家店（stop）返回 `print` 出单状态，订单返回 `pickupCode`。后台订单详情里能看到出单状态和异常原因。

### 后台

代买服务 → 店铺管理 → 每家店的"出单打印机"，可以：
- 开关出单、选品牌、填名称和 SN；
- 填凭证：编辑时留空的密钥保持不变；
- 飞鹅云填了设备 KEY，保存时会自动把设备添加到店家的飞鹅账号；
- 打印测试页、查询在线状态（仅飞鹅）、删除打印机。

### 小票自由编辑（2026-10-07 追加）

用户决定：
- 模板范围：每家店可以单独设置，另有一套区域默认模板。
- 编辑方式：模块化编辑，配实时预览。

数据：
- 区域默认模板存在 `configs` 表，key 为 `purchase_ticket_template:<regionId>`。
- 店铺自定义模板存在 `printer_configs.ticketTemplate`，为空表示沿用区域默认。
- 实际出单时按"店铺模板 → 区域模板 → 系统内置模板"的顺序选用。
- 打印联数记在 `print_jobs.copies`，飞鹅用 `times` 参数、芯烨用 `copies` 参数实现。
- 以上两个字段已加进同一个迁移 202610060003；PostgreSQL 版本重新验证过，零差异。

模块：
- 字段类：取餐码、店名、订单号、接单时间、骑手、备注。
- 其他：多店提示（只在合单时打印）、商品列表（必选）、自定义文字、分隔线、空行、二维码（最多一个，最多 120 字）。

每个模块可以：
- 开关、上移下移、删除；
- 改前缀；
- 选字号（标准 / 加高 / 加宽 / 放大）、对齐（左 / 中 / 右）、是否加粗。

商品列表还可以设置是否显示规格、是否显示价格、数量是否放大。

全局设置：纸宽（58 / 80mm）、联数（1 到 3）、来单语音、自动切纸。

自定义文字支持这些变量：取餐码、店名、订单号、接单时间、骑手、备注、件数、货款、第几家、店铺数。
用户写在模板里的 `<` `>` 会转成全角字符，所以模板不可能写出打印指令。

后台入口：
- 代买服务 → 新增"出单小票"页，编辑区域默认模板，可以一键恢复系统默认；
- 店铺 → 出单打印机 → "小票样式"页，可以选"使用区域默认"或"本店自定义"。

预览和测试：
- 预览由后端用同一套渲染代码生成示例订单，前端再把飞鹅标签画成近似样式，二维码会画成真实的码。
- "打印测试页"按这家店已保存的模板打一张示例单，顶部标明"测试小票，请勿制作"。

系统内置模板和原来写死的小票逐字一致，原有的 13 个小票用例全部照常通过。
编辑器已在浏览器里实际操作过：打字不会失去焦点，上移下移、关掉商品列表时的报错、添加二维码、切换 80mm、加高和加宽都正常。

待真机确认：飞鹅文档没有说明标签能否嵌套。"居中 + 放大"用的是官方组合标签 `<CB>`；其他组合（比如"居中 + 加高"）是嵌套写法，需要用"打印测试页"看一下实际效果。

### 小票编辑优化（2026-10-07 追加）

按用户选的三项做了优化：

- **拖拽排序**：按住模块左侧的 ⋮⋮ 拖动，拖动中会显示落点提示线。原来的上移、下移按钮保留。只有按住手柄才能拖，所以在输入框里选文字不受影响。
- **预览定位**：
  - 后端按模块分段渲染小票（`renderTicketParts`），每段记着它来自第几个模块。
  - 点预览里的某一行，左侧对应模块会高亮并滚动到可见位置。
  - 鼠标停在模块上时，预览里对应的行也会高亮；反过来停在预览行上，模块也会高亮。
- **一键套用和复制**：
  - "套用样式 / 复制"菜单里有三套现成样式：标准、简洁、后厨大字（定义在后端的 `TICKET_PRESETS`，都有用例保证能通过校验）。
  - 同一个菜单还能复制区域默认小票，或者复制其他店铺的自定义小票。
  - 套用前会弹窗确认；套用后在保存前都还能继续改。

以上三项都在浏览器里实际操作验证过（临时预览页面，用的是真实的后端渲染代码）。

### 关于"微信支付的打印机"（2026-10-07 调研）

结论：**微信支付没有对第三方开放打印机接口，目前没法像飞鹅那样接入。**

- 检索了微信支付文档中心的完整目录（品牌经营、商户、服务商三套 llms.txt），和打印、小票、设备相关的只有两项，都不是打印机接口：
  - "电子小票"：商户把小票做成图片，随支付凭证推送给付款人；
  - "商家小票"：点金计划里付款后展示的商户自定义页面。
- 微信支付官方的 4G 小票机在"微信商家助手 / 收款小账本"里绑定收款码使用，打印的是微信收款记录（以及微信小商店订单），没有对外的接口可以推送代买订单。
- 下一步：拿到机器后，看机身标签上的生产厂家或云平台名称。这类机器很多是映美、商米、中午云、博实结等厂家生产的，如果厂家自己的云平台开放接口，就按那家的文档接入，接法和飞鹅一样（我们服务器发单）。
