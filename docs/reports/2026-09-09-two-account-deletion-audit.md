## 注销触发证据

Nginx 在 09:50:05、09:50:12 分别记录了 `POST /api/auth/user/cancel-account`，两次 HTTP 状态均为 201，与两个数据库注销时间逐秒对应。各自随后一秒的重复请求返回 401。

此接口使用 JwtGuard，并从已验证令牌的 `sub` 取当前账号 ID；正常流程没有接受请求方传入另一个目标用户 ID。结合数据库时间、状态和缺失的管理员操作记录，证据支持这两个账号是经账号自助注销接口注销。

两次成功注销请求来自 `43.141.50.132`；随后重复请求来自 `43.141.50.236`。请求 User-Agent 和两个账号保存的登录 User-Agent 均包含 `Tencent Security Team`，设备描述为 Windows 微信小程序环境。这个标识提示安全检测流量；仅凭 User-Agent 不能确认官方身份，因此不能断言是某个真人主动点击，也不能把调用方归属当作已取得官方确认的事实。

当前注销接口不接收注销理由，历史记录中也没有保存个人注销动机；可以查明触发接口及时间，无法补出当时没有记录的理由。

## 后台为什么看不到

1. **状态被错误合并。** `backend/src/modules/admin/admin.service.ts:1951` 的列表返回逻辑只区分 ACTIVE、BANNED，其他状态统一返回 disabled，因此 DELETED 被显示为“禁用”。详情返回在同文件约 2637 行也有相同逻辑。
2. **缺少自助注销审计。** `backend/src/modules/user/user.service.ts:1803` 的注销事务修改账号和档案，之后撤销会话，没有写入 AuditLog。两个账号实际的用户审计总数也都是 0。
3. **成功请求日志有采样。** `backend/src/interceptors/request-log.interceptor.ts:199` 对普通成功请求仅按 1% 采样，所以这两次注销成功请求未进入后台可查询的 server_logs；Nginx 访问日志保留了请求证据。
4. **详情没有展示用户状态事件。** `admin/src/views/modules/UsersPage.vue:310` 只展示后台操作人、动作、模块和时间，没有展示自助注销事件或日志详情中的理由。

列表对非 active 用户通用显示“启用”按钮，也没有把已注销用户单独处理。注销已清除昵称以外的部分个人资料，不能把普通启用按钮当作完整账号恢复流程。

## 建议方案

- **A，推荐：** 分开显示正常、禁用、封禁、已注销；返回注销时间；自助注销在同一事务中记录来源、时间和账号状态变化，并在详情展示状态历史。已注销账号不提供普通启用、封禁按钮。历史事实只能据现有证据显示，不能虚构旧的注销理由。
- **B：** 只把状态文字改为“已注销”。改动更小，但仍无法查看触发来源和历史原因，因此不推荐作为完整修复。

本记录仅完成原因核查，上述修复尚未实施。
