# 小程序校园地图 UI 方案 A（本地完成）

范围：桌面「前端文件」的校园地图首页、地点预览卡和展开详情。沿用原有校园插画、发布数据、导航规则和客服反馈接口。本轮未部署后端、上传小程序、调整真实地点或搜索开关。

## 本轮实现

- 搜索框改为清楚的「搜索校园地点」，分类按学生常用程度排序。原始分类为 building 的地点显示「楼宇」，不擅自归为教学楼。
- 默认视图保留编号和可读名称，不再等到 135% 缩放才出现名称。公寓短名称仅用于标签，全名保留在地点详情和辅助标签中。
- 标签在屏幕边界、搜索栏和工具栏之间避让；仅调整显示位置，不写入地点、锚点或路线数据。继续保留既有“不把标签引导线画成导航路线”的约束。
- 定位、放大、缩小和重置统一使用项目已有图标。去掉常驻缩放百分比，底部提供轻量浏览提示。
- 地点名称成为卡片主体，距离改为辅助信息。移走黑色距离块，减少重复名称和地址；建设阶段放入次级信息。
- 增加明确的展开、收起和关闭控件，保留上滑/下滑手势。入口和实景有清楚的分区，照片展示面积增大，底部主要操作固定可见。
- 无可用导航时，展开详情解释原因；仍依照现有条件显示居中查看、开始导航、返回导航或到达打卡。
- 「居中查看」在普通浏览时先收起大卡片，再聚焦地点，防止目标被详情覆盖；从搜索结果进入地点也会聚焦。

## 顺带纠正的显示与搜索问题

1. 旧地点卡片使用插画坐标差值显示米数。本轮改为 GCJ 坐标计算直线距离，并明确标注「直线距离」。它不代表实际步行路线长度。
2. 定位投影落在地图范围外时清除旧位置和距离，显示「当前定位在地图范围外」。定位失败和权限未开启分别提示，已有画布定位标记也会清除。
3. 搜索索引补带 publishStatus 与 artworkPositionResolved，避免已发布且美术位置已解析的地点在二次筛选时失去资格。未公开、已撤回及 searchable=false 的地点仍不会进入搜索结果。

## 现有配置与验收边界

- 为核对搜索表现，本轮只读检查了现有公开地图接口。当前返回 16 个公开地点，其中 3 个关闭搜索；学生餐厅的 searchable=false。因此学生餐厅能点选但不出现在搜索结果，符合当前配置。本轮未绕过或修改这个开关。实际搜索验收使用 searchable=true 的「天工楼」。
- 本轮预览仍连接旧后端。控制台持续存在 /campus-map/version 的 404，前端走既有完整接口兼容逻辑；不是“线上新版后端已上线”的证据。未将控制台累计错误数描述为零。
- 实测设备为微信开发者工具 iPhone 12/13 (Pro) 模拟器。户外可读性、真机字体/触摸、真实定位精度、行走导航仍需单独验收。
- 标签采用有限的避让候选；本轮可见地点已检查。后续地点数量大幅增长时，需要再验证密集标签的可读性。
