# 骑手 App 后台定位与弱网补传设计

**日期：** 2026-07-28  
**状态：** 已确认（路线 B）  
**范围：** 真机持续定位、离线缓存、轨迹补传、后台控制参数

## 目标

让审核通过的官方骑手在存在配送中订单时，App 进入后台后仍可持续采集位置；网络不可用或请求失败时先保存到本机，恢复网络后按批补传，并由服务端幂等入库形成可追溯轨迹。

## 约束

- 仅官方骑手且存在配送中订单时启动，订单结束、退出登录或后台关闭开关时立即停止。
- 不引入第三方定位 SDK；App 使用系统定位能力，iOS 声明后台 location 模式，Android 使用项目内 UTS 前台定位服务并声明对应权限。
- 本地队列有上限，默认 300 点；超限淘汰最旧点，不无限占用存储。
- 单批最多 50 点；每点携带客户端唯一编号和采集时间，服务端按唯一编号去重。
- 客户端采集时间不得晚于服务器五分钟；过旧点由后台配置控制，默认最多补传 24 小时。
- 只提交数据库迁移源文件，不连接或改动生产数据库。

## 数据流

1. 工作台或订单详情发布当前官方骑手资格、活动订单编号。
2. 定位协调器读取后台控制配置；允许时启动原生持续定位监听。
3. 每个有效点先写入本地持久化队列，再尝试批量上传；上传失败不丢点。
4. 网络恢复、App 回到前台、取得新定位点时都会触发补传。
5. 服务端校验骑手资格、活动订单归属、坐标、时间和批量上限；按 `clientId` 幂等写入轨迹表。
6. 每批最后一个有效点继续更新现有骑手最新位置，兼容实时地图。

## 后台控制

“骑手 App 控制中心”的运行参数增加：

- 后台定位总开关；
- 本地轨迹队列上限（50-1000）；
- 单次补传数量（1-50）；
- 最长补传时效（1-72 小时）。

## 验收

- 纯函数测试覆盖队列上限、去重、成功移除、失败保留和批量切分。
- 后端测试覆盖非官方骑手、无活动订单、越权订单、非法点、重复点和批量上限。
- Android/iOS manifest 具备对应权限与后台模式；App 前后台切换不重建重复监听。
- 断网产生的位置保留在本机，恢复网络后补传；服务端重复接收不产生重复轨迹。
- 后端全量测试、类型检查、后台构建和 App 测试通过。

## 真机发布门槛

源码与模拟器通过不等于真机后台能力已验收。Android 必须使用包含定位前台服务能力的自定义基座或正式安装包，iOS 必须使用已签名安装包，并分别完成锁屏、切后台、弱网/断网、系统回收后的轨迹验证。
