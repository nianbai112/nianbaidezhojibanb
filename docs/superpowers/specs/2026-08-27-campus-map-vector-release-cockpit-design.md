# 校园地图矢量发布指挥台设计

日期：2026-08-27

## 1. 决策

校园地图对用户只展示重庆城乡发展职业学院的画师 SVG 矢量图。画师 SVG 是完整的用户地图视觉表面，不是后台参考图。

高德地图、卫星图、CAD 工程图层、GCJ-02 坐标和骑手原始轨迹仅用于后台校准、采集、审核和导航计算，任何情况下都不能作为用户端的可见底图或降级页面。

本期同时把后台校园地图页面从“功能平铺的地图编辑器”整理为“发布指挥台”，让运营人员围绕阻塞项完成地点核验、草稿确认和正式发布。

允许删除、合并和重构现有组件与入口；不以保留旧页面结构为目标。判断标准是普通用户是否好用、好看，运营人员是否能快速完成工作，而不是功能数量是否增加。

## 2. 术语边界

- **用户地图**：画师 SVG、正式公开地点、已审核入口、已发布导航路线和用户当前位置。
- **工程底图**：高德、卫星图、CAD、原始采集轨迹和校准控制点，只在后台可见。
- **地点档案**：数据库中的稳定地点记录，保存编号、名称、开放状态、照片、真实坐标和发布状态。
- **地图草稿**：审核结果写入后、尚未正式上线的可编辑版本。
- **正式版本**：不可变的发布快照，小程序只消费当前激活的正式版本。

“不展示底图”在本设计中专指不向用户展示工程底图；画师 SVG 是用户地图本身，必须完整展示。

## 3. 目标

### 3.1 后台目标

- 打开校园地图后立即看清档案、核验、发布候选、正式版本和用户在线五个阶段。
- 每个阶段显示数量、状态和最优先的阻塞原因，点击阶段即可筛选对应地点。
- 默认只突出“补地点”“派采集”“发布本批”三个主操作。
- 运营人员进入页面后十秒内能够判断当前最重要的阻塞项和下一步操作。
- CAD 导入、版本历史、高级设置和停用地图归入次级运维操作。
- 继续使用现有地点档案、草稿、版本、质量检查和发布验证，不新建重复状态表。

### 3.2 用户端目标

- 页面始终使用画师 SVG 全屏渲染，保持建筑、道路、水系和绿化的原始插画风格。
- 用户可以搜索正式公开地点、点击标记、查看照片和入口、发起校内导航。
- 正式版本没有地点时显示明确空状态，绝不展示内置地点假装已经发布。
- SVG 加载失败时显示可重试错误，绝不回退到高德或微信原生地图。
- 搜索、分类、地点详情和导航浮层不大面积遮挡地图，颜色和圆角沿用现有小程序视觉变量。

## 4. 非目标

- 不重画、不裁切、不替换画师 SVG。
- 不引入第二套用户地图样式，不增加真实地图/矢量图切换开关。
- 不开发三维地图、室内楼层导航、热力图或 AI 自动审核。
- 不重写现有后端发布内核，不新增发布批次数据库表。
- 不为了兼容旧布局而保留重复按钮、重复状态说明或重复入口。
- 不在本设计阶段迁移生产数据库、写入真实学校数据或执行正式发布。
- 不同时扩展小程序隐藏采集器和骑手 App；专业现场采集继续以骑手 App 为主。

## 5. 方案选择

### 5.1 采用方案：现有系统内的状态驱动改造

复用当前 Vue 工作台、地点档案、骑手审核、草稿和不可变发布版本，只新增纯前端派生状态和界面重排。

优点：改动小，不迁移数据，不改变接口，不影响已经完成的证据链和发布安全边界；可以逐步上线和回滚。

### 5.2 不采用：新建独立发布中心

独立页面会重复加载地图、地点、采集和版本数据，还会让运营人员在两个页面之间切换。本期没有足够收益支撑新的路由、权限和状态同步成本。

### 5.3 不采用：重新制作一张程序化矢量地图

画师 SVG 已经是正式视觉资产，重新绘制会产生风格偏差、锚点漂移和双份维护。程序只负责叠加交互数据，不复制画师作品。

## 6. 后台发布指挥台

### 6.1 五阶段状态栏

状态全部由现有数据实时派生：

1. **档案绑定**：地点具有稳定 `placeId`、正式编号和画师锚点。
2. **现场核验**：地点具有骑手审核通过的 GCJ-02 坐标；需要入口或照片时证据完整。
3. **发布候选**：地点为 `published + phase1_active`，开放状态可解释，且已绑定画师锚点。
4. **正式版本**：地点已经进入当前激活的不可变版本。
5. **用户在线**：公共接口返回当前新版本且公开地点数大于零。

每个阶段显示“完成数 / 总数”。阶段为红色时显示首个必须修复项，为橙色时显示建议项，为绿色时显示已完成。

### 6.2 主操作

- **补地点**：打开地点档案并聚焦缺少稳定绑定或画师锚点的地点。
- **派采集**：打开现场采集，默认带入当前选中或核验不完整的地点。
- **发布本批**：打开发布检查；存在必须修复项时不得绕过。

保存草稿继续自动执行，但在顶部清楚显示“未保存”“草稿 rN”“线上 vN”和公开地点数量。

### 6.3 运维操作

以下操作进入一个次级菜单，不与主流程争夺视觉优先级：

- CAD 导入
- 地点档案全量管理
- 版本历史与回滚
- 高级设置
- 停用地图
- 刷新数据

### 6.4 问题队列

右侧检查器在没有选中地图对象时显示问题队列，按以下顺序排序：

1. 没有稳定地点绑定或画师锚点。
2. 未来建筑错误进入一期可见层。
3. 缺少现场核验坐标、入口或必需照片。
4. 未开放建筑缺少用户说明。
5. 导航入口没有连接已审核路网。
6. 草稿已变化但尚未正式发布。
7. 正式版本已生成但公共接口未返回新版本或公开地点为零。

点击问题后复用现有 `selectLayerItem`、地点档案抽屉和采集抽屉，不创建第二套编辑器。

### 6.5 审核对比

地点核验继续使用现有按字段选择的合并机制。界面明确显示：

- 当前档案值
- 骑手候选值
- 证据质量
- 本次是否合并

审核通过只写入地点档案和地图草稿，不直接修改正式版本。

## 7. 小程序矢量地图

### 7.1 渲染合同

- WXML 不再保留可渲染的微信原生 `<map>` 分支。
- `useNativeMap` 固定为 `false`，只允许 SVG 图片层和 Canvas 交互覆盖层。
- 后端 AMap/GCJ-02 数据仍可用于坐标投影和导航计算，但不能决定用户端渲染模式。
- 画师 SVG 路径固定来自随包资产 `/campusMap/assets/cqcx-campus-map.svg`。
- 后端远程图片地址不能替换画师 SVG。

### 7.2 正式数据合并

- 使用正式编号和画师锚点把公开地点合并到本地 SVG。
- 后端新增地点只有在提供有效画师锚点后才能进入用户图层。
- 地点名称、开放状态、照片、入口、搜索和导航权限以当前正式版本为准。
- 内置 38 个锚点只负责定位画师建筑，不赋予地点公开资格。

### 7.3 视觉规则

- SVG 保持完整比例，缩放和平移不得拉伸或露出空白边缘。
- 搜索框、分类和地点详情使用半透明白色浮层，继续复用现有品牌色和文字变量。
- 地点标记使用单一高对比品牌蓝；未开放状态只改变徽标和文案，不给地图铺大面积警示色。
- 默认不展示内部道路工程线、区域多边形、校准点和骑手轨迹。
- 导航时只叠加经过审核的路线和用户位置，路线应覆盖在 SVG 道路上。
- 搜索、清除和定位优先使用小程序原生图标或项目现有图标资产，不新增字符画图标。

### 7.4 失败状态

- 没有正式地图：显示“校园地图暂未开放”。
- 正式版本公开地点为零：显示“地点资料正在整理”，不显示内置地点。
- SVG 加载失败：显示“矢量地图加载失败”和重试按钮。
- 当前位置无法投影：仍可浏览和搜索，只停用定位与校内导航。
- 路网不连通：地点详情仍可用，但导航按钮停用并解释原因。

所有失败状态都禁止回退到真实地图。

## 8. 数据流

```text
画师 SVG 与稳定锚点
  + 地点档案
  + 骑手现场证据
  -> 管理员按字段审核
  -> 地图草稿 rN
  -> 发布质量检查
  -> 不可变正式版本 vN
  -> 公共地图接口
  -> 小程序把正式数据覆盖到画师 SVG
```

## 9. 代码边界

### 9.1 后台

- `CampusMapActionBar.vue`：改造成五阶段发布指挥区和主操作区。
- `campusMapReleaseModel.mjs`：新增纯函数，负责阶段统计、问题排序和首要行动推导。
- `campusMapReleaseModel.test.mjs`：覆盖派生状态与排序。
- `RegionCampusMapPainter.vue`：提供现有地点、质量检查、版本和公开接口数据；不再新增业务状态。
- `CampusMapInspector.vue`：无选中对象时显示派生问题队列。

### 9.2 小程序

- `campusMap/index/index.wxml`：移除用户可见的原生地图分支。
- `campusMap/index/index.js`：保持 SVG 唯一渲染模式，并拒绝远程底图替换。
- `campusMap/index/index.wxss`：只做与画师地图相协调的浮层、标记和状态视觉收敛。
- `minitest/campus-map-page.test.cjs`：锁定 SVG 唯一用户地图合同。

### 9.3 后端

本期不增加接口和数据表。继续使用现有地点档案、草稿、发布版本、公共接口和骑手审核服务。

## 10. 测试策略

所有行为改动遵循测试先行。

### 10.1 后台自动化

- 阶段统计在空数据、部分完成、全部完成时正确。
- 问题队列按发布风险排序。
- `phase1_review` 不被当作用户公开。
- 公共接口版本未推进或公开地点为零时，“用户在线”不得通过。
- 运行校园地图管理端聚焦测试和 `npm run typecheck`。

### 10.2 小程序自动化

- WXML 不包含可渲染的原生 `<map>`。
- 运行时始终设置 `useNativeMap: false`。
- 远程 AMap 包不能替换随包画师 SVG。
- 后端没有公开地点时内置锚点不可搜索、不可点击、不可导航。
- SVG 失败只进入错误状态，不进入真实地图。
- 运行全部校园地图聚焦测试。

### 10.3 视觉验收

- 后台在 1440px 宽度下检查五阶段状态、主操作和问题队列层级。
- 小程序使用微信开发者工具检查搜索关闭、搜索展开、地点选中、导航中和错误状态。
- 同一视口对比画师 SVG 原图和小程序截图，确认无拉伸、裁切、空白边和真实地图泄漏。
- 真机检查缩放、平移、标记点击和弱网重试。

## 11. 验收标准

- 普通用户无法通过任何页面状态看到高德、卫星图、CAD 或骑手原始轨迹。
- 用户端始终展示随包画师 SVG；SVG 不可用时明确失败，不做真实地图降级。
- 未正式发布的地点不出现在搜索、标记或导航中。
- 后台打开页面即可看到五阶段完成度和首要阻塞项。
- 主流程只有补地点、派采集和发布本批三个高优先级操作。
- 正式发布必须通过现有质量检查并重新验证公共接口版本和公开地点数量。
- 不新增运行时依赖、不新增后端表、不修改生产数据。

## 12. 实施顺序

1. 先以测试锁定“小程序只能展示画师 SVG”的渲染合同。
2. 新增后台发布阶段纯模型及测试。
3. 改造后台顶部指挥区和无选中对象的问题队列。
4. 收敛小程序浮层和标记视觉，不改画师 SVG 内容。
5. 运行后台、小程序、后端和骑手端回归检查。
6. 在本地迁移和登录态具备后完成后台截图与微信开发者工具视觉验收。
