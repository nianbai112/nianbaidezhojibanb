# 骑手 App 配送履约闭环设计

**日期：** 2026-07-28  
**状态：** 已确认  
**范围：** 导航、送达凭证、配送异常上报

## 目标

让已接单的官方骑手能够从订单详情完成真实配送操作：打开系统地图前往取货点或送达点、上传送达照片、报告无法联系/地址错误等异常，并让异常直接进入现有后台异常订单处理链路。

## 约束

- 不新增 Prisma 模型或迁移，复用 `DeliveryOrderNode` 与 `DeliveryRiskEvent`。
- 普通订单送达照片可选；现有风控规则要求凭证时必须上传至少一张。
- 骑手不能自行确认完成订单，只能标记送达并等待用户确认。
- 异常接口只允许审核通过、官方、已绑定区域且订单属于当前骑手的账号调用。
- 不引入地图或上传第三方依赖，使用 UniApp 原生能力和现有 `/upload` 接口。

## 数据流

1. 订单详情返回取货/送达地址、可用坐标以及 `delivery_proof_required`。
2. 有坐标时调用 `uni.openLocation`；无坐标时打开系统地图的地址搜索链接，不伪造坐标。
3. 骑手点击送达时可选取最多三张照片，经现有上传接口得到 HTTPS/站内 URL，再与当前位置一起提交状态更新。
4. 风控单无照片时 App 先拦截；服务端现有状态机再次强制校验。
5. 异常上报写入一条未处理 `DeliveryRiskEvent`，同时写入 `DeliveryOrderNode`，后台现有“异常订单”立即可见。

## 异常类型

- `merchant_delay`：商家未出餐/取货等待
- `cannot_contact`：无法联系用户
- `address_issue`：地址错误或无法进入
- `vehicle_issue`：车辆或设备故障
- `other`：其他配送异常

说明必填 5-300 字；凭证图片最多三张。同一订单、骑手、异常类型存在未处理记录时返回已有记录，避免重复点击制造多条告警。

## 验收

- 跑腿单与外卖单均能打开取货导航；有送达坐标时能打开送达导航。
- 风控单无照片不能送达，上传成功后照片进入配送节点。
- 非订单骑手、兼职骑手、已结束订单不能上报异常。
- 上报后后台异常订单能读取对应风险事件。
- 后端全测、后台构建、App 单测和 iOS 模拟器编译通过。
