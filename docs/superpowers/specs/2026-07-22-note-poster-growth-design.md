# 笔记分享海报与拉新归因设计

## 目标

把笔记的“分享海报”做成完整的传播闭环：登录用户可将图文笔记分享到站内联系人和群聊、微信好友/群、朋友圈或保存图片；未注册者从海报二维码或小程序分享卡进入后，完成首次注册会按当前区域的“分享有礼”规则归因并结算奖励。

## 已确认的产品规则

- 分享按钮只对当前已进入小程序的用户使用；海报页不得因生成二维码跳转登录页。
- 不论笔记有没有原图，外部分享都必须有图、有文字、有可回流的小程序入口。
- 分享有礼只对未注册的新用户有效；扫码、打开笔记或重复登录本身不产生奖励。
- 奖励继续使用现有 `ShareSettings`、`ShareInvite`、`ShareReward`、钱包和优惠券能力，不创建第二套奖励账本。
- 微信用户由微信原生分享面板自行选择好友、微信群或朋友圈；小程序不得伪造“已分享”或代替用户选择联系人。

## 现状与问题

- `pagesC/post/posterShare.js` 调用 `/upload/unlimited-qrcode`。该接口只允许后台管理员，普通用户会先收到 401 并被全局请求逻辑跳去登录；即使管理员调用，页面也漏传服务端必填的 `scene`。
- 现有笔记海报配置仅有背景色、Logo、底部文案和二维码位置，不能上传背景/透明框，也未与区域分享有礼关联。
- 私聊 `notes:` 卡片采用 7 段竖线字符串；群聊使用另一种 4 段格式，点击和渲染不能可靠共用。
- 分享有礼已有配置、限额、防刷、奖励和补发能力，但入口使用明文 `inviter_id`，与笔记分享没有稳定关联；当前“新用户”判定为账号 7 天内，不能证明该归因发生在注册前。

## 方案选择

### 方案 A：仅修复二维码接口

将当前二维码接口改成普通用户可用，并补 `scene`。实现快，但没有模板管理、来源归因、站内卡片统一格式或注册前保存邀请信息，不满足增长闭环。

### 方案 B：客户端动态合成 + 短分享码归因（采用）

后台保存模板资产和布局参数；小程序用现有 painter 把笔记内容和动态小程序码合成海报。服务端为每次外部分享创建不可猜的短码，扫码/分享路径只携带短码。注册完成后才消费短码并调用现有奖励规则。该方案不增加服务端图片渲染依赖，模板可运营，归因可审计。

### 方案 C：服务端渲染整张海报

由后端生成 PNG 并存储。视觉最统一，但会引入字体、图片下载、渲染进程、缓存和故障恢复等运行依赖；当前小程序已有绘制能力，属于不必要扩张。

## 用户体验与渠道契约

### 海报内容

每张海报固定包含：

- 笔记主图：取第一张可访问图片；纯文字、音频或没有图片时使用后台模板的内容占位图，不允许空白。
- 笔记标题：优先标题，否则正文前 32 个可见字符。
- 正文摘要：去除换行后最多 70 个可见字符。
- 作者显示名和头像：匿名笔记使用后端已脱敏后的匿名身份，不泄露真实作者。
- 圈子/区域名称、品牌 Logo、后台 CTA 文案。
- 小程序码与“扫码查看笔记”提示。

外部分享卡片的标题使用标题或正文短摘要；分享图片使用已生成的海报。小程序路径/朋友圈 query 使用同一短分享码，保证没有二维码时也可以归因。

### 站内联系人与群聊

统一采用 `note-share:v2:<JSON>` 消息体，字段为 `postId`、`title`、`summary`、`coverUrl`、`authorName`、`authorAvatar`、`circleName`、`regionId`、`shareCode`、`createdAt`。私聊和群聊共用同一解析器与同一可点击卡片；卡片显示封面、标题、摘要和来源，点击始终跳到 `/pagesB/post/post?id=<postId>`。

站内接收者已经是注册用户，只记录内容分享事件，不参与“拉新人”奖励。发送必须经现有 WebSocket 私聊/群聊接口并保留成员、禁言、拉黑和幂等校验。

### 微信好友、微信群、朋友圈与保存图片

- 微信好友/微信群：调用原生小程序分享，由用户选择联系人或群；携带标题、合成海报图和带短码的小程序路径。
- 朋友圈：使用原生朋友圈分享；携带标题、合成海报图和 `shareCode` query。
- 保存图片/图片分享：保存同一张含二维码的海报；支持的微信版本通过原生图片分享菜单打开入口。
- 若小程序环境不支持图片分享，仍保留保存到相册，并提示用户从相册发送；不伪造成功状态。

## 后台模板管理

在现有“内容设置 > 笔记海报配置”中扩展为模板配置，而不是把活动分享图混入区域分享设置。模板字段：

- 启用状态、模板名称、默认模板。
- 背景图、透明内容框 PNG、Logo、纯文字占位图、二维码外框图。
- 海报尺寸与内容安全区：封面、标题、摘要、作者、二维码、CTA 的坐标和尺寸。
- 字体颜色、背景色、CTA 文案、二维码位置。
- 模板预览数据与发布版本号。

首期只支持一个全局默认模板和一个可选的区域覆盖模板；不做自由拖拽编辑器。运营可以上传“框框”素材，开发只维护固定安全区，避免用户上传图片后覆盖动态文字或二维码。

## 短分享码与二维码

新增 `PostShareLink` 记录，至少包含：`code`（唯一、短且不可猜）、`postId`、`sharerId`、`regionId`、`channel`、`templateVersion`、`createdAt`、`openedAt`、`claimedAt`、`claimUserId`、`status`。`code` 只承载在微信 `scene`（例如 `s=Ab3K9x`）和分享路径/query 中；服务端根据 code 恢复笔记、分享者和区域。

普通用户调用新的受限接口创建短码和小程序码。服务端只允许已发布、未删除且当前访问者可访问的笔记；二维码生成服务不再开放后台上传接口给小程序端。二维码调用参数为：

```json
{
  "scene": "s=Ab3K9x",
  "page": "pagesB/post/post",
  "width": 430,
  "checkPath": true
}
```

二维码生成需要限流、按 `postId + sharerId + templateVersion` 缓存、COS 存储失败可重试。小程序码不会在数据库中长期暴露分享者身份。

## 注册归因与分享有礼结算

1. 新设备从二维码或分享路径进入笔记页时，小程序解析并本地暂存 `shareCode`，然后正常展示已发布笔记。
2. 若该访问者已存在账户，不参与拉新；若尚未注册，短码保留到微信登录完成。
3. 首次成功创建用户账户后，客户端调用“认领笔记分享”接口，只提交短码；服务端从登录身份、创建时间、设备 ID、IP 和短码记录判定归因。
4. 服务端原子校验：活动启用/时段、分享者与新用户不相同、短码有效、账号为首次创建、没有已成功或待处理邀请、区域一致、既有手机号/学生认证/黑白名单/次数/预算/IP/设备限制。
5. 校验通过时由同一事务创建 `ShareInvite` 和双方 `ShareReward`，并沿用现有 immediate、manual、delayed、qualified 的发放模式以及优惠券配置；失败时写拒绝原因和审计事件，绝不发钱。
6. 短码只能被一名新用户成功认领；认领后的扫码仍可正常打开笔记，但不会再次奖励。

“新用户”定义改为：短码首次进入发生在该用户创建前，且该用户在认领时尚未存在有效 `ShareInvite`。不再以“注册 7 天内”替代首次注册。

## 数据、权限与可观测性

- `PostShareLink` 为归因事实来源；`ShareInvite`/`ShareReward` 为奖励事实来源。
- 后台按区域筛选模板、分享链接、扫码、注册认领、奖励状态与拒绝原因；运营可查看漏斗：海报生成 → 外部分享 → 打开 → 注册 → 合格 → 奖励成功。
- 用户接口只可为本人创建分享码；不得传任意 `sharerId`、`regionId` 或奖励金额。
- 模板编辑需要内容/系统配置权限；奖励补发继续使用现有 `share:reward` 权限。
- 帖子删除、下架或访问受限后，短码打开返回“笔记不可查看”，不再生成新海报或发放奖励；历史奖励不回滚。

## 验收场景

1. 图文笔记：生成海报含首图、标题、摘要、作者、圈子、二维码；扫码直达同一笔记。
2. 纯文字笔记：生成海报使用占位图，仍有文字和二维码，不出现空图。
3. 私聊与群聊：同一 `note-share:v2` 卡片在历史消息、实时消息、本人和他人视角均可显示并可打开。
4. 微信分享：好友/群、朋友圈、保存图片均使用同一短码；取消分享不写“已成功分享”。
5. 新用户：扫码 → 注册 → 首次登录后，满足活动条件只创建一次邀请和两笔奖励/优惠券；重复扫码、重复认领、同设备/IP 超限和非新用户均不得重复奖励。
6. 活动关闭、活动过期、帖子下架、二维码服务失败、COS 失败、模板资源不可用均有可理解的前端提示、后台记录和可重试边界。
7. 管理员更换模板后，新海报使用新版本；旧海报仍可扫码回流且按照创建时活动快照归因。
