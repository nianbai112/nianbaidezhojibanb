# 校园路线双几何规划、采集与发布设计

日期：2026-09-02

## 1. 决策与目标

本设计采用已确认的方案 A：一条校园道路保持一个稳定路线身份，同时分别保存真实路线几何和画师图展示几何。

- 高德规划和骑手实采使用 GCJ-02 真实经纬度。
- 小程序继续以现有画师 SVG 作为用户主地图。
- 真实路线偏离画师路线时，不修改真实路线去迎合画师图。
- 后台可以单独调整画师图覆盖线，但不能借此改变导航几何。
- 路线采集任务进入“待采集”前必须绑定至少一条可用的规划路线。
- 骑手端必须明确显示蓝色目标路线和橙色实采轨迹，不能再创建无目标的正式路线任务。

最终主链固定为：

```text
后台高德图粗规划真实路线
  -> 保存路线规划候选
  -> 在画师图生成或人工确认展示线
  -> 绑定路线并派发骑手任务
  -> 骑手沿蓝线采集橙色实轨
  -> 后台对照规划线、实轨和画师线审核
  -> 实轨成为已核验真实路线
  -> 明确开启公开
  -> 校验入口和路网连通性
  -> 正式发布
  -> 小程序用真实路网计算、用画师线展示
```

## 2. 当前问题

当前实现同时存在以下断点：

1. 后台运营主画面被固定为画师 SVG，高德地图只用于坐标选择，无法承担真实路线规划。
2. GCJ-02 路线在没有 `artworkGeometry` 时不会显示在画师工作台。
3. 在画师图上新画的路线只有 `xRatio/yRatio`，高德坐标模式保存时只接受经纬度点，因此该路线不能成为有效的 GCJ-02 规划路线。
4. 路线采集任务允许 `targetFeatureIds` 为空，骑手端可以收到没有蓝色目标线的正式任务。
5. 规划路线、实采路线和用户展示路线的职责没有在后台界面中明确分开。

这些问题不能通过增加操作说明解决，必须修正数据阶段、后台画布和任务校验边界。

## 3. 核心原则

### 3.1 真实几何是导航事实源

高德规划候选和骑手审核实轨都使用 GCJ-02。审核通过后，`sourceGeometryGcj02` 是路线计算、距离、偏航和入口连接的唯一几何事实源。

画师图上的任何拖动、吸附或美化都不能回写 `sourceGeometryGcj02`。

### 3.2 展示几何只负责画师图视觉

`artworkGeometry` 保存同一路线在画师 SVG 坐标系中的展示折线。它可以经过自动投射、人工修正和视觉简化，但不参与真实距离和最短路径计算。

### 3.3 路线身份与几何版本分离

路线在规划、派采、审核和发布期间保持稳定 `routeId`。规划几何被实采几何替换时，不创建一个与任务失联的新路线身份。

### 3.4 拓扑一致优先于像素重合

两条线是否属于同一路线，优先检查起点、终点、经过的路口顺序和入口连接，而不是要求像素形状完全重合。

## 4. 路线数据模型

路线继续保存在校园地图 manifest 的 `operator_routes` 图层中，不新增第二套发布存储。核心结构为：

```json
{
  "type": "Feature",
  "geometry": {
    "type": "LineString",
    "coordinates": [[106.0, 29.0], [106.1, 29.1]]
  },
  "properties": {
    "id": "route-stable-id",
    "semanticType": "road",
    "routeStage": "planned",
    "plannedGeometryGcj02": {
      "type": "LineString",
      "coordinates": [[106.0, 29.0], [106.1, 29.1]]
    },
    "sourceGeometryGcj02": null,
    "artworkGeometry": {
      "type": "LineString",
      "coordinates": [[420, 850], [510, 910]]
    },
    "displayAlignmentStatus": "manual_confirmed",
    "collectionSource": "admin_planned",
    "verificationStatus": "pending_collection",
    "public": false
  }
}
```

字段职责：

- `plannedGeometryGcj02`：管理员在高德图上绘制的采集目标，只用于派采参考，不得进入公开导航。
- `sourceGeometryGcj02`：骑手实采并经审核的真实路线；审核前为空。
- `geometry`：工作草稿当前使用的坐标几何。规划阶段指向规划候选；审核后由服务端重建为可信实轨或其画师投影。
- `artworkGeometry`：画师 SVG 展示线。
- `routeStage`：`planned`、`collecting`、`review`、`verified`、`published` 或 `retired`。
- `displayAlignmentStatus`：`missing`、`auto_projected`、`manual_review` 或 `manual_confirmed`。
- `routeEndpointAnchors`：仅在实采审核通过后由服务端生成可信路口锚点；规划阶段不能伪造该字段。
- `public`：保持现有显式公开开关；规划和新审核路线默认 `false`。

既有已审核路线继续使用现有 `sourceGeometryGcj02`、`collectionSource=rider_app_approved` 和 `routeEndpointAnchors`，不需要数据库迁移。

## 5. 后台双画布工作流

### 5.1 高德真实路线规划

后台地图工作台新增明确的“真实路线规划”视图：

- 使用现有高德 JS SDK 标准底图。
- 管理员沿真实道路连续点击绘制折线。
- 每条路线必须在路口处分段，不能用一条长线跨越多个独立路口。
- 支持移动节点、撤销、重做、拆分和删除规划候选。
- 保存后生成稳定 `routeId` 和 `plannedGeometryGcj02`。
- 规划路线始终显示为蓝色候选线，并明确标记“尚未实采，不可发布”。

高德底图自带道路不自动进入系统。只有管理员主动保存的规划候选才可以成为采集任务目标。

### 5.2 画师图展示线

保存真实规划线后，系统尝试使用至少三个分散、非共线的“真实坐标 + 画师锚点”地点生成画师图候选线。

- 自动结果只标记为 `auto_projected`，不能直接公开。
- 管理员可以在画师 SVG 上单独拖动和简化展示节点。
- 画师线编辑器只写 `artworkGeometry`。
- 没有足够校准点时，允许先保存真实规划线，但不能把该路线公开到用户地图。
- 新道路不要求修改原始 SVG 文件，使用后台管理的路线覆盖层显示。

### 5.3 偏差审核

后台对同一路线同时展示：

- 蓝色：管理员规划的 GCJ-02 候选。
- 橙色：骑手实际采集轨迹。
- 绿色或画师风格线：`artworkGeometry`。

偏差处理规则：

1. 起终点和路口顺序一致，仅线形不同：允许采用实轨，并单独确认或调整画师线。
2. 起终点或路口顺序不同：进入 `manual_review`，不得公开。
3. 实轨证明存在画师图未表现的新道路：保留实轨，新增画师覆盖线。
4. 实轨证明规划路线不可通行：拒绝或要求补采，并将规划候选标记为停用或重新规划。

首版不根据单一像素距离自动判定同一路线，避免艺术化变形导致误判。发布以人工确认拓扑一致为准。

## 6. 采集任务约束

### 6.1 创建和变更

- `route_collection` 任务可以作为空目标草稿保存，但不能进入 `ready`。
- 任务进入 `ready` 时，前端和后端都必须校验 `targetFeatureIds.length >= 1`。
- 每个目标必须属于当前学校、存在于最新草稿、`routeStage=planned` 或 `verified`，并且具有至少两个有效 GCJ-02 点。
- 任务开始采集后不得更换目标路线；需要变更时取消旧任务并创建新任务。
- 历史已完成或待审核的空目标任务保持可审计，不做破坏性回写。

### 6.2 骑手端启动门槛

骑手端读取任务时：

- 目标规划线使用蓝色粗线。
- 已审核参考道路使用绿色线。
- 当前实采轨迹使用橙色线。
- 如果正式路线任务没有可投影目标线，禁止开始并提示“该任务缺少后台规划路线，请管理员重新派发”。
- 参考建筑或其他非目标图层加载失败时可以降级，但目标路线本身不能静默缺失。

## 7. 审核写回规则

骑手提交路线对象后，后台以任务绑定的稳定 `routeId` 为写回目标：

1. 服务端继续执行现有点数、精度、距离、间隔、ACK 和端点锚点校验。
2. 审核页对照 `plannedGeometryGcj02` 与实际轨迹，但不能用规划线覆盖实轨。
3. 审核通过后，将服务端 ACK 轨迹写入 `sourceGeometryGcj02`。
4. `collectionSource` 更新为 `rider_app_approved`，`verificationStatus` 更新为 `verified`。
5. 规划阶段字段保留为审计证据，不参与导航。
6. `artworkGeometry` 保持独立；拓扑冲突时设置 `displayAlignmentStatus=manual_review`。
7. 新审核路线继续默认 `public=false`，必须由管理员明确开启。

如果旧流程产生了新的 `collection-route-{objectId}`，实施时需要兼容读取；新流程优先更新任务绑定的稳定路线，不再制造重复路线身份。

## 8. 发布与小程序消费

发布编译仍只接受：

- `collectionSource=rider_app_approved`；
- `verificationStatus=verified`；
- `public=true`；
- 可步行、未封闭、非施工；
- 具有可信 `routeEndpointAnchors`；
- 入口和全校路网连通检查通过。

新增发布阻断：公开路线缺少 `artworkGeometry` 或 `displayAlignmentStatus` 不是 `manual_confirmed`。

小程序职责保持分离：

- 路径计算、距离、偏航和到达判断只读取已发布 `sourceGeometryGcj02` 路网。
- 画师 SVG 路线覆盖层只读取 `artworkGeometry`。
- 用户当前位置通过已核验坐标与画师锚点投射到 SVG。
- 画师图展示失败不得篡改真实导航线；应明确降级为暂不开放该路线展示或导航。

## 9. 接口和兼容边界

优先复用现有接口：

- 校园地图草稿保存继续承载规划路线和画师展示线。
- 采集任务接口继续保存 `targetFeatureIds`，增加状态转换校验。
- 骑手任务详情继续返回 `referenceMap`，但目标路线优先读取 `plannedGeometryGcj02`。
- 对象审核接口继续完成可信实轨写回，改为优先更新稳定 `routeId`。

本设计不要求新增 Prisma 表或生产数据库迁移。字段位于现有 manifest JSON 和任务 JSON 中。若实现过程中发现现有审计能力不能保存稳定路线身份，再单独提出迁移，不在本设计中预设新表。

## 10. 错误处理

- 高德 SDK 未加载：禁止创建真实规划路线，保留已保存草稿，不回退到伪造经纬度。
- 规划路线少于两个有效点：禁止保存。
- 画师投射控制点不足：真实规划可保存，但路线不能公开。
- 任务目标为空或目标已删除：禁止进入待采集和禁止骑手开始。
- 骑手实轨与规划拓扑冲突：禁止审核为可公开状态，要求人工确认、重新规划或补采。
- 公开路线缺少已确认画师线：发布阻断，不自动生成一条看似正确的用户线。
- 并发修改草稿：沿用 revision 冲突机制，要求重新加载，不静默覆盖审核写回。

## 11. 测试与验收

### 11.1 后台

- 高德画布可以创建、编辑、拆分并保存 GCJ-02 规划路线。
- 画师画布可以编辑 `artworkGeometry`，且不会改变真实经纬度。
- 已有 GCJ-02 路线在高德规划视图可见。
- 无目标路线任务不能进入 `ready`。
- 审核页能同时区分规划线、实轨和画师线。

### 11.2 后端

- `route_collection + ready + targetFeatureIds=[]` 返回明确错误。
- 不存在、跨学校或无有效 GCJ-02 几何的目标不能派采。
- 骑手 `referenceMap` 对目标规划线标记 `targeted=true`。
- 审核通过更新稳定路线身份，并以 ACK 实轨重建 `sourceGeometryGcj02`。
- 规划线不能进入公开导航编译。
- 缺少已确认 `artworkGeometry` 的公开路线阻断发布。

### 11.3 骑手端

- 蓝色目标路线、绿色参考道路和橙色实轨同时存在且含义固定。
- 目标路线缺失时不能开始采集。
- 弱网恢复后仍使用同一个目标路线和稳定路线身份。

### 11.4 小程序

- 路径计算只使用已核验真实路网。
- 画师地图只绘制已确认展示线。
- 调整画师线不会改变距离、导航步骤或偏航判断。
- 调整真实路线不会在未重新确认画师线时绕过发布阻断。

### 11.5 验收边界

代码测试通过不等于正式上线完成。最终还需要：

- 在线后台创建一条真实规划路线并成功派采。
- 新安装骑手 APK 真机看到蓝色目标线并完成一段采集。
- 后台审核后确认同一稳定路线被更新，没有产生重复路线。
- 正式发布版本号前进，公共接口返回新版本。
- 微信真机确认画师线展示与真实导航同时正确。

## 12. 实施顺序

1. 先补数据契约和状态校验测试。
2. 恢复后台高德真实路线规划画布，并保存规划候选。
3. 强制正式路线任务绑定目标并修复骑手端缺线启动门槛。
4. 修改审核写回，使实轨更新稳定路线身份。
5. 增加画师线投射、人工确认与发布阻断。
6. 完成三端专项测试、构建和本地联调。
7. 再进行生产部署、任务创建和真机验收。

该顺序优先修复“骑手不知道怎么走”的核心断点，再开放正式路线发布，避免在展示对齐完成前产生错误导航。
