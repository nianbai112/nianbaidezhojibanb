# 校园地图运营闭环设计

## 目标

在不改动小程序通用页面渲染器的前提下，把现有校园地图从“能画、能直接发布”升级为运营者可安全维护、用户可实际查找和导航的校园地图：运营端明确区分草稿与线上版本，支持版本历史和回滚；公开端只消费已发布地图；小程序提供地点搜索、分类筛选、地点详情和系统导航。

## 已批准边界

- 沿用已有 CampusMap、CampusMapDraft、CampusMapVersion 数据模型和后台接口，不重做发布内核。
- 继续保留旧 `PUT /admin/campus-map/:regionId` 作为兼容接口，但新运营工作台不再调用它。
- 当前 `components/page-renderer/page-renderer.wxml` 编译错误由用户处理，本批不修改该文件。
- 不新增地图 SDK、搜索 SDK或另一套对象存储；小程序使用已经发布的中性 GeoJSON 和微信原生地图能力。
- 不写真实区域数据、不执行生产数据库迁移、不部署生产环境。
- 前端与后端改动分别核对；当前工作区已有用户改动，禁止回退无关文件。

## 运营端工作流

运营者的主流程固定为：编辑 -> 保存草稿 -> 发布检查 -> 发布 -> 查看版本历史/回滚。

`GET /admin/campus-map/:regionId` 返回顶层可编辑 manifest，并在 `workflow` 中返回 `draftRevision`、`activeVersion` 和 `activeVersionId`。保存草稿调用 `PUT /draft` 并携带 revision；发布调用 `POST /publish` 并携带刚保存成功的 revision。409 冲突提示运营者重新加载，不静默覆盖。

工作台显示当前线上版本、草稿 revision 和“有未保存修改”状态。版本抽屉分页展示版本号、发布时间、要素数、图层数和体积；回滚必须二次确认，回滚成功后重新加载画板。

## 发布规则

- 启用的地图必须有底图或有效点线面。
- 图片/CAD 模式若开启定位或需要距离/导航能力，至少需要两个有效校准点；该项从建议升级为发布阻断。
- 未命名对象和未完成绘制仍可作为警告，由运营者确认后发布。
- 后台预览明确标注为结构预览，不把它作为小程序真机验收。

## 停用与回退

区域地图停用后不返回该区域旧版本。公开读取继续尝试全局已发布地图；若没有全局地图，返回 `not_configured`。后台确认文案必须与该规则一致，不再声称回到本地示例地图。

## 小程序用户能力

地点索引从已发布的 POI、建筑标签、出入口和建筑面生成，保留名称、分类、描述、语义类型、地图坐标以及可用的经纬度。

- 搜索：按名称、描述和分类本地过滤，不发额外网络请求。
- 分类：从语义类型生成常用分类，默认“全部”。
- 详情：点击搜索结果或地图标记后统一展示地点名称、分类、描述和距离。
- 导航：有 GCJ-02 经纬度时调用 `wx.openLocation`；图片/CAD 地图用两点校准的反向投影换算经纬度。没有可靠坐标时明确提示运营者先完成校准，不伪造路线。
- 反馈：使用微信原生 `open-type="feedback"`，不新增无落库能力的伪接口。

## 导入任务恢复

导入任务仍保存在区域 Config JSON 中。本批只解决单进程可确认的问题：进程启动时把遗留的 `queued/processing` 标记为失败并提示运营者重试；同一区域的读改写操作进程内串行化，避免本进程并发覆盖。多实例 worker 需要独立任务表和数据库抢占锁，超出本批范围并在代码中明确边界。

## 验收

- 后端测试覆盖停用区域回退全局、无全局时未配置、导入任务启动恢复。
- 静态控制面测试覆盖草稿 API、发布 API、版本列表、回滚、工作台按钮和干净版本同步。
- 小程序单元测试覆盖地点索引搜索、分类、校准反投影和导航参数。
- admin build、backend build、校园地图专项测试全部通过。
- 微信开发者工具编译仅记录用户负责的 WXML 阻塞，不修改该文件，也不把编译通过作为本批虚假结论。
