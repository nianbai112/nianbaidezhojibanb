# 校园地图学校与建筑开通管理设计

日期：2026-08-02

## 1. 背景

现有校园地图已经具备 CAD/GeoJSON 导入、后台绘制、草稿保存、发布、版本历史、回滚、搜索和导航能力。当前一期单栋建筑语义化设计还区分了已建项目与后续在建项目，但“地图是否对某所学校开放”和“某栋已建建筑是否对用户开放”尚未形成可运营的双层状态。

本设计在现有地图发布链路上增加学校级和建筑级开通管理。运营人员可以在后台新增、删除和编辑建筑，也可以设置整所学校或单栋建筑为已开通/未开通，并填写用户可见的未开通说明。

## 2. 目标

- 后台可以按学校查看、修改校园地图开通状态。
- 学校未开通时可以填写用户可见的说明。
- 后台可以新增、编辑和删除单栋建筑或设施。
- 已建建筑可以分别设置已开放或未开放，并填写未开放说明。
- 学校和建筑状态随草稿、发布版本与回滚保存。
- 小程序正确展示未开通说明，并阻止对未开放建筑发起导航。
- 保持一期真实几何、未来项目隔离和原有数据安全边界。

## 3. 非目标

- 不新增独立建筑业务表或第二套地图发布系统。
- 不把宣传鸟瞰图作为真实几何来源。
- 不把二、三、四期在建项目自动发布给用户。
- 不在本轮引入重型 3D 地图引擎。
- 不在未经确认的情况下修改数据库真实草稿、发布生产地图或部署服务器。

## 4. 采用方案

沿用 `CampusMapDraft.manifest` 和 `CampusMapVersion.manifest`：学校级状态存入地图 manifest，建筑级状态存入 GeoJSON feature properties。后台所有修改先进入草稿，只有发布后才进入活动地图；版本回滚同时恢复学校和建筑状态。

不采用独立建筑表，原因是独立表会产生地图版本与建筑状态不同步、回滚不完整和额外迁移问题。现阶段建筑数据仍属于一张地图的可视化发布内容，放在版本化 manifest 中最稳妥。

## 5. 状态模型

### 5.1 学校级状态

地图 manifest 增加：

```json
{
  "availability": {
    "status": "open",
    "unavailableMessage": ""
  }
}
```

字段规则：

- `status` 只允许 `open` 或 `unopened`。
- `unavailableMessage` 最长 200 个字符。
- 发布版本中 `status=unopened` 时，说明不能为空；草稿可以暂时留空。
- `status=open` 时，后台清空未开通说明，避免旧说明再次显示。
- 该状态与现有 `enabled` 含义不同：`enabled` 表示技术上存在可发布地图；`availability.status` 表示该学校对用户的业务开放状态。

### 5.2 建筑级状态

已建建筑或设施的 GeoJSON properties 增加：

```json
{
  "serviceStatus": "open",
  "unavailableMessage": ""
}
```

字段规则：

- `serviceStatus` 只允许 `open` 或 `unopened`。
- `unavailableMessage` 最长 120 个字符。
- 发布版本中 `serviceStatus=unopened` 时，说明不能为空；草稿可以暂时留空。
- 活动图层中的未开放建筑仍然可见、可搜索，但 `navigable` 必须为 `false`。需要从用户端彻底移除时，应删除该建筑或移出活动图层，不能用“未开放”代替隐藏。
- 已开放建筑是否可以导航，仍取决于 `navigable=true`、有效目标坐标和地图校准。
- `constructionStatus=under_construction` 的未来项目继续遵守一期设计：只在后台参考层，不进入用户活动地图；不能通过 `serviceStatus` 绕过该边界。

### 5.3 兼容默认值

- 老版本 manifest 没有 `availability` 时按 `open` 处理，避免已发布学校突然变成未开通。
- 老建筑没有 `serviceStatus` 时，已建且当前可搜索的对象按 `open` 处理。
- 未来或在建对象仍以 `constructionStatus` 和 `visibilityScope` 为准，不套用兼容默认值公开展示。

## 6. 后台交互

### 6.1 学校开通管理

在区域配置的校园地图页增加“学校开通状态”区域：

- 状态开关：已开通 / 未开通。
- 未开通说明输入框，仅在未开通时显示并必填。
- 当前草稿状态、当前已发布状态分别显示，避免运营人员误以为保存草稿已经对用户生效。
- 区域/学校列表显示校园地图状态标签：已开通、未开通、未配置；可以按状态筛选。

学校状态修改遵循现有流程：保存草稿后不立即影响用户，发布新版本后生效。

### 6.2 建筑管理

后台继续使用现有点位和建筑绘制能力：

- “新增点位”用于入口、停车场或暂时没有可靠轮廓的建筑。
- “圈建筑”用于具有可靠 CAD 轮廓的单栋建筑。
- 属性面板可以编辑正式名称、编号、语义类型、开放状态和未开放说明。
- 图层列表为每栋建筑显示“已开放”或“未开放”标签，并支持状态筛选。
- 删除建筑需要二次确认；删除只修改草稿，发布后用户端才移除。
- 误删建筑可以通过撤销、重新加载未发布草稿或发布版本回滚恢复。

### 6.3 发布检查

以下情况禁止发布：

- 学校状态为未开通但没有说明。
- 未开放建筑没有说明。
- 未开放建筑仍开启导航。
- 建筑名称为空、官方编号重复或几何无效。
- 在建/未来项目进入用户活动图层、搜索或导航。
- 图片/CAD 地图不满足既有校准要求。

## 7. 后端行为

### 7.1 保存与发布

`normalizeAdminPayload` 规范化学校级 `availability`，并保留建筑 feature properties 中的 `serviceStatus` 与 `unavailableMessage`。`saveDraft` 只保存草稿；`publishDraft` 在创建新版本前执行学校与建筑状态校验。

### 7.2 活动地图接口

`GET /campus-map/active` 按以下优先级处理：

1. 请求学校存在已发布版本，且 `availability.status=unopened`：返回该学校自己的未开通状态与说明，不回退到全局地图。
2. 请求学校存在已发布且已开通的地图：返回活动地图。
3. 请求学校没有明确发布记录：保留现有全局地图回退行为。
4. 没有区域地图和全局地图：返回未配置状态。

显式未开通和未配置必须区分。显式未开通使用 `reason=school_unopened`，并携带经过长度限制的 `unavailableMessage`；接口继续只返回转换后的显示数据，不返回原始 CAD 或上传源文件。

### 7.3 学校状态总览

后台增加区域范围内的校园地图状态查询，返回学校/区域标识、地图标题、开通状态、未开通说明摘要、草稿修订号和已发布版本号。该接口沿用管理员区域数据权限，不允许跨区域读取。

## 8. 小程序体验

### 8.1 学校未开通

用户进入明确未开通的学校地图时，显示独立状态页：

- 学校或地图名称。
- “校园地图暂未开通”状态。
- 后台填写的说明。
- 返回学校首页按钮。

该页面不显示其他学校地图，也不提供地图搜索和导航。

### 8.2 建筑未开放

- 地图上保留建筑轮廓和名称，使用蓝灰色、降低饱和度并显示“暂未开放”标志。
- 搜索结果保留该建筑并显示未开放标签，让用户知道地点存在。
- 点击后显示正式名称、类型、开放状态和未开放说明。
- 导航按钮显示禁用状态，文案为“暂未开放”。
- 不只依赖颜色表达状态，必须同时提供文字标签。

### 8.3 已开放建筑

已开放建筑沿用选定的轻量 2.5D 导览风格。点击后显示距离与导航；只有坐标和校准有效时才允许调用 `wx.openLocation`。

## 9. 数据流

1. 管理员进入学校/区域的校园地图配置。
2. 修改学校状态，或新增、编辑、删除建筑。
3. 保存草稿，后台返回新的草稿修订号。
4. 发布检查校验状态说明、几何、未来项目边界与导航条件。
5. 发布生成不可变版本并更新活动版本。
6. 小程序重新请求活动地图。
7. 小程序根据学校和建筑状态展示地图、说明与导航权限。
8. 需要恢复时，从版本历史回滚，学校与建筑状态一并恢复。

## 10. 异常处理

- 草稿修订冲突：沿用乐观锁，提示重新加载，不覆盖其他管理员修改。
- 非法状态值：后端按请求错误拒绝，不静默纠正为已开放。
- 缺少未开通说明：保存草稿允许暂存，发布时必须拦截。
- 建筑删除：必须确认；已发布版本不立即改变，直到新版本发布。
- 小程序收到未知状态：按未开放处理并禁用导航，避免误导用户。
- 活动地图请求失败：显示加载失败和重试，不把接口错误误报为学校未开通。
- 老版本数据：按兼容默认值读取，不强制迁移历史 JSON。

## 11. 验收标准

### 后台

- 可以查看学校的已开通、未开通和未配置状态。
- 可以填写并发布学校未开通说明。
- 可以新增点位、圈出建筑、修改属性和删除建筑。
- 可以设置单栋已建建筑已开放或未开放，并填写说明。
- 草稿和已发布状态在界面上明确区分。
- 发布检查可以拦截所有无说明、错误导航和未来项目泄漏情况。

### 后端

- 学校与建筑状态完整经过草稿、发布、版本和回滚。
- 明确未开通的学校不会回退到全局地图。
- 未配置学校仍保持现有回退规则。
- 未开放建筑的公开数据保留说明但强制不可导航。
- 活动接口不暴露原始 CAD、上传路径或后台参考图层。

### 小程序

- 学校未开通时显示后台说明，不显示其他学校地图。
- 未开放建筑可见、可搜索、可查看说明，但无法导航。
- 已开放且坐标有效的建筑可以正常导航。
- 删除并发布的建筑不再显示；版本回滚后可以恢复。

### 真实链路

- 后台新增一栋测试建筑并保存草稿。
- 设置建筑未开放并填写说明，发布新版本。
- 微信开发者工具刷新后可以搜索该建筑、查看说明且导航禁用。
- 后台将学校设为未开通并发布，小程序显示学校说明且不回退。
- 回滚到前一版本后，小程序恢复原学校和建筑状态。
- 真机导航、定位和性能作为独立验收，不以本地测试或编译替代。

## 12. 实施边界

实施分为后端规则、后台编辑、小程序展示三个可独立验证的部分。后端/admin 与小程序属于不同仓库，必须分别保存变更和验证。实现阶段不自动写入真实校园地图草稿、不执行发布、不部署生产；真实数据发布和真机验收需要单独确认。
