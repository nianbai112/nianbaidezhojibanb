# Campus Map Field Collection Phase One Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a secure, recoverable phase-one campus field-collection loop: admins create scoped collection tasks and custom marker templates, an assigned mini-program user records foreground GCJ-02 tracks and markers with offline recovery, and admins inspect immutable raw sessions without publishing them into the live campus map.

**Architecture:** Add a collection bounded context beside the existing campus-map draft/version subsystem. Admin APIs use existing admin guards and regional data scope; collector APIs use ordinary mini-program JWT plus task assignment and a short-lived hashed access code. The mini-program collector is a hidden subpackage page with pure, testable cache/chunk helpers. Raw points and marker snapshots are append-only; the admin drawer is a phase-one task/session/raw-data console, not a route editor. PostgreSQL remains the migration provider, while the existing schema sync script keeps PostgreSQL/MySQL Prisma variants identical.

**Tech Stack:** NestJS 11, Prisma 5, PostgreSQL migration SQL, Jest, Vue 3, Element Plus, Vite, Node `node:test`, compiled WeChat mini-program JavaScript/WXML/WXSS, WeChat foreground location APIs.

## Global Constraints

- Preserve every pre-existing dirty or untracked file in both repositories. Never use `git add .`, `git reset --hard`, `git checkout --`, or broad cleanup commands.
- Keep backend/admin and mini-program commits separate because they are different repositories.
- Do not modify `backend/src/modules/campus-map/campus-map.controller.ts`; it already has unrelated local edits. Add a separate collection controller.
- Do not add the collector to a public menu, tab bar, home card, or search entry. The only entry is a task link/QR generated by the admin workbench.
- Do not put an admin bearer token in the mini-program. Collector requests use the signed-in ordinary user JWT, assigned user ID, and short-lived task access code.
- Use GCJ-02 for all collected positions. Do not silently convert CAD plane coordinates into longitude/latitude.
- Raw points, marker snapshots, and attachments are immutable source records. Phase one may change task/session review status, but may not rewrite or delete raw geometry.
- Phase one does not clean tracks, create routing graph edges, save a campus-map draft, publish a version, deploy, or claim device acceptance.
- Do not request background location. Use `wx.startLocationUpdate`, `wx.onLocationChange`, `wx.stopLocationUpdate`, and `wx.setKeepScreenOn` only while the collector page is foregrounded.
- All mutation endpoints must be idempotent where a retry can occur. Client session IDs, client point IDs, batch numbers, and client marker IDs are stable across retries.
- Every admin route must enforce `JwtGuard`, `AdminGuard`, `AdminPermissionGuard`, `region:view` or `region:edit`, and `AdminDataScopeService.assertRegionAccess`.
- Every collector route must enforce `JwtGuard`, reject admin tokens, verify active task, assigned collector, matching access-code hash/expiry where required, and ownership of the session.
- Test commands prove only local static/unit/build behavior. WeChat DevTools, Xiaomi device, real GPS, weak-network recovery, and production deployment remain explicit acceptance gates.
