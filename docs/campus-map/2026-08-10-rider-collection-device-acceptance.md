# 骑手端校园地图现场采集：部署与真机验收

## 本次范围

- 后端：专业采集任务、官方骑手分配、五类采集对象、幂等上传、审核状态。
- 管理后台：创建任务、选择本区域已审核官方骑手、查看会话和逐对象审核。
- 骑手端 App：任务入口、实时轨迹、道路/建筑/入口/设施/异常、照片与录音、离线补传、断点续采、Android 独立前台定位服务。
- 小程序：本次不修改。

## 部署顺序

1. 备份数据库。
2. 部署后端代码并执行生产数据库迁移。
3. 启动后端，确认健康检查正常。
4. 部署管理后台构建产物。
5. 重新制作并安装骑手端 Android 测试包；UTS 前台服务改动不能只做热更新。

## 后台创建首个任务

1. 进入“区域中心 → 校园地图 → 现场采集”。
2. 新建任务，客户端勾选“骑手端 App”。
3. 选择需要的对象类型：道路、建筑、入口、设施、异常。
4. 选择当前区域已审核的官方骑手，填写优先级、截止时间、范围和现场说明。
5. 状态改为“待执行”并保存。
6. 被分配骑手重新进入 App 工作台后，应出现“现场采集”卡片。

## 小米 Android 权限准备

1. 定位权限选择“始终允许”，并开启精确位置。
2. 允许通知，以便看到“校园地图采集中”的常驻通知。
3. 在系统电池设置中将骑手端设为“不限制”，允许后台活动和自启动。
4. 首次开始采集时保持网络可用，以创建服务端会话；之后断网仍可继续记录并补传。

## 真机验收清单

- [ ] 未分配任务的骑手看不到现场采集入口。
- [ ] 被分配的官方骑手可以看到任务，但不能打开其他区域或其他骑手的任务。
- [ ] 开始后地图实时显示当前位置和行走轨迹，屏幕保持常亮。
- [ ] 通知栏显示“校园地图采集中”，并且与“官方骑手配送中”通知互不影响。
- [ ] 暂停后不再增加有效轨迹点，屏幕恢复系统亮屏策略；继续后恢复记录。
- [ ] 道路少于 2 个点无法保存；建筑少于 3 个顶点无法保存。
- [ ] 入口、设施、异常使用当前位置生成点对象。
- [ ] 入口可以选填绑定建筑 ID；对象可以填写名称、分类、开放状态、无障碍、说明。
- [ ] 可以拍摄最多 6 张照片，并可录制 60 秒以内语音备注。
- [ ] 断网后轨迹、对象、照片和录音保留在本机，工作台显示待补传数量。
- [ ] 恢复网络点击“补传”后，只有服务端 ACK 的数据从队列移除。
- [ ] 上传期间继续走动，新产生的定位点不会被旧上传快照覆盖。
- [ ] App 退到后台再回来，可以恢复当前任务；结束 App 进程后重开仍能读取本机会话。
- [ ] 完成任务前会强制补传；仍有未确认数据时不能误报完成。
- [ ] 后台能看到会话、轨迹点、五类对象和附件。
- [ ] 后台逐对象执行“通过 / 要求重采 / 暂缓 / 作废”后状态和说明正确保存。
- [ ] 审核对象不会直接覆盖已发布校园地图；正式地图仍需单独发布流程。
