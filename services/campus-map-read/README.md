# 校园地图 Go 读取服务（B 方案第一阶段）

独立 Go 进程，只读已发布地图。没有数据库写权限，没有审核、发布、采集接口；不接管画师图编辑和手机绘图。原 NestJS 仍是唯一写入方。

## 数据路径

```text
管理员/骑手 → NestJS → 采集、审核、草稿、发布（保持原流程）
                         ↓ 已发布快照 + 实时公开过滤
                    Go 定时同步、原子替换
                         ↓
学生/官网 → Nginx → Go 内存快照（预压缩、版本校验）
                    └─ 学生受保护接口 → Nest JwtGuard / 账号状态检查
```

此阶段减少地图查库/序列化的重复工作，不消除登录校验的数据库依赖。不能将其宣传为“原后端宕机仍可完整使用”，更不是双机高可用。

## 已实现的保护

- 固定学校白名单，最多 64 个；未知学校不会触发数据库查询或无限增大缓存。`global` 必须显式列入，才能兼容不传区域的旧请求。
- 访问者不会触发同步；每个学校仅有一个后台同步循环，全局最多 4 个同步请求。
- 默认同步间隔 2s（上次同步结束后计时），租期 5s（从同步开始计时）。超过租期立即停止返回旧快照，无 stale-if-error，无无限延长缓存。
- 服务端传播窗口不等于已打开客户端的强实时撤回。客户端仍需重新请求才能看到更新；上线必须验证页面恢复/导航会话更新行为。
- 错误或超时不会覆盖上次成功快照，但旧快照只能在原租期内使用，不能续期；学校停用、地点/照片撤回会改变内容摘要，即使正式版本号不变。
- 内存缓存预算 64MiB，原始单包最多 8MiB，最多 64 个活动请求；过载快速返回 429，不堆积无限队列。
- 已发布校验：拒绝错误地区、错误业务码、没有发布版本的 enabled 地图、显式 draft 字段、HTML 假成功和超大响应。
- 登录令牌不落盘、不共享缓存、不写日志；每次受保护读取和 304 都复用原 JwtGuard，保留封禁/注销校验。
- 内部登录校验额外要求服务密钥，限流额度按令牌摘要区分，避免把同一校园 NAT 下的学生合并。只修改这个新增入口，不改原业务限流规则。
- 原后端只新增内部快照和轻量访问校验入口，内部快照用独立随机密钥 + 回环来源校验，不能使用 JWT_SECRET；不跟随上游重定向。
- HTTP 超时、健康与就绪探针、结构化日志、计数指标、优雅退出；进程内没有 JWT 签名密钥，也没有 MySQL/Redis 凭据。
- Nginx 示例默认仍指向 Nest；没有自动故障回源，防止 Go 过载把核心订单 API 一并拖垮。

## 接口兼容

GET/HEAD `/campus-map/site`：与官网公开读取一致。

GET/HEAD `/campus-map/active`：必须登录，调用 Nest `/campus-map/read-access` 完成原账号状态检查。

GET/HEAD `/campus-map/site/version` 和 `/campus-map/version`：分别为匿名/受保护的轻量内容版本查询，不含坐标和路网。

以上均接受 `/api` 前缀、`region_id` / `regionId`，重复冲突参数拒绝。输出保持原公开包结构。当前 Nest 在公开过滤后生成 `readRevision`，Go 校验并沿用，避免灰度/回切时因两种语言的序列化差异反复刷新；旧 Nest 未提供摘要时由 Go 补充。摘要包含撤回后的公共内容，不使用变化频繁的响应时间戳。

Nest 现在同样提供 `/campus-map/version` 和 `/campus-map/site/version`，便于统一前端轮询与手动回切。Nest 版本接口仍读取公开地图并计算摘要，减少的是响应体，不能当成无数据库开销的缓存命中。

2026-09-05 的方案 A 已补齐前台轮询、隐藏页面清理、导航前复核、入口约束和旧路网导航暂停，详见 [修复与验收报告](../../docs/reports/2026-09-05-campus-map-plan-a.md)。

识别原 Nest `TransformInterceptor` 的数字成功码 `0`，兼容数字 `200`，保持地图响应原成功码；错误码、缺失/null/字符串成功码均不当作成功。受保护读取同样按实际 Nest 响应验证。

`/healthz` 只检查进程存活；`/readyz` 要求白名单所有学校都有未过期快照；`/metrics` 暴露快照就绪、请求、拒绝、校验失败、同步成功/失败和缓存字节数。三个运维接口仅在本机使用，不加入公网反代。

画师 SVG 仍走原静态路径；此服务不负责缓存私有媒体或管理员草稿，也不会自动使画师图渲染变快。

## 本地验证

要求 Go 1.25+，当前开发验证工具链为 Go 1.26.2；仅依赖标准库。

```sh
go test -race -count=1 ./...
go vet ./...
go test -run '^$' -bench BenchmarkCachedPublicMap -benchmem ./...
go build -o bin/campus-map-read .
node --test process-smoke.test.cjs
```

基准仅是内存热缓存 + 合成 55KB 数据，不包含 TLS、真实登录、数据库、真实手机网络，不能转换成线上可承诺的同时在线人数。

`process-smoke.test.cjs` 启动本机 Go 二进制和模拟 HTTP 上游，验证新旧响应内容一致、512 次受保护读取、撤回、上游异常、恢复和进程重启。使用随机本地端口及测试凭据，结束时关闭进程；不连接真实 Nest、数据库或生产。不能替代真实鉴权和 Nginx 联调。

后端 `campus-map-go.integration.spec.ts` 则加载真实 Nest HTTP 控制器、地图公开过滤、JWT 签名验证、守卫、限流、前缀兼容中间件和响应拦截器，连接 Go 二进制。设置 `CAMPUS_MAP_TEST_BINARY` 为本机二进制绝对路径后，在完整依赖的后端目录执行：

```sh
node node_modules/jest/bin/jest.js --runInBand --runTestsByPath src/modules/campus-map/campus-map-go.integration.spec.ts
```

未设置二进制时这组测试明确跳过。Prisma 使用内存测试替身，不连接数据库，不启动主 AppModule 的订单、支付、定时任务；不能将通过结果称为真实数据库或生产容量验收。

可再设置 `CAMPUS_MAP_TEST_NGINX` 为本地测试 Nginx 二进制绝对路径、`CAMPUS_MAP_TEST_DEPLOY_DIR` 为本仓库 deploy 目录绝对路径，启用另外两项入口测试。测试基于本仓库 Nginx 示例生成临时配置，先执行 `nginx -t`，再验证默认 Node、切换 Go、隐藏内部接口和手动回切；不修改生产配置。回切用新建测试进程验证配置行为，不等于生产平滑 reload 已验收。

## 回切与高可用边界

- 回切：将 Nginx map 的 upstream 改回 `http://127.0.0.1:3000`，先 `nginx -t` 再 reload。必须按核心 API 的实际容量限流，不能无限回源。
- Go 重启：内存缓存为空，在同步完成前 503；不得从未经新鲜性确认的旧磁盘包恢复开放路线。
- Node/数据库故障：受保护接口无法重新确认账号，返回 503；公开快照最多服务到剩余租期结束。不能为了“看起来没死”悄悄绕过权限或长期继续公开撤回内容。
- 同机 CPU/内存限制仅减少争抢；主机、磁盘、网络、MySQL 仍是共同故障点。开学的整机故障保障需要另行建设备用实例/负载切换、数据恢复与 CDN，不包含在“换 Go”里。

官方依据：[Go HTTP 超时/退出](https://go.dev/src/net/http/server.go)、[Go 内存软限制](https://go.dev/pkg/runtime/)、[NGINX 请求限流](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)。GOMEMLIMIT 不是硬内存隔离，示例同时使用 systemd MemoryMax。
